# The decision index

Everything in `design/native/` is decided. This file is the index: one row per
decision close enough to be worth arguing, the document that argues it in full,
and the alternative that lost. Where a row and its document disagree, the
document is right — this is a table of contents, not a second source.

Nothing here is open. A reversed decision is reversed in the document that made
it, and the reversal is recorded there rather than deleted.

| Decision | Where | The alternative that lost |
|---|---|---|
| Reference counting, not a GC | MEMORY.md §3 | A tracing GC needs statepoints or conservative scanning. Statepoints contradict CODEGEN-LLVM.md §0's second instruction; conservative scanning makes the heap data-dependent and irreproducible. |
| `Checked` is bounded by the numbers the *backend* has | VALUE-MODEL.md §11, SPEC §6.2.2 | A native backend that also stopped at 2^53 shipped for a wave and was reversed: it makes `Checked` useless on `I64` natively, and buys portability of a result nobody should branch on. |
| `Str` slicing keeps its parent buffer alive, and that is not a language question | MEMORY.md §5.3, §6 | Copying above a ratio makes `slice` name `Alloc` and retracts `core/str`'s purity claim. Copying on proven retention is a real analysis for a case that is hard to detect, and it stays available precisely because it is not language-visible. |
| Exactly one supported LLVM at a time, tracking the latest both inkwell and the flake carry | CODEGEN-LLVM.md §8.1–8.3 | "The flake leads" forbids a bump the backend needs. "The backend leads" prices a nixpkgs bump — which moves `cargo`, `bun` and `elan` — into a routine chore. Multi-version support is refused permanently: two LLVMs means one attribute encoded two ways. |
| No arena per `Alloc` scope | MEMORY.md §4 | `Alloc` is a propagating bound and `Region` is a value; there is no scope to hang an arena on. |
| The middle end owns tail-call elimination; no backend uses its own | CODEGEN-LLVM.md §5 | `musttail`/`tailcc` and `return_call` are both viral, both incompatible with a C-ABI runtime, and both unnecessary once the tail-call graph is a DAG. |
| Neither linker links incrementally; recompile granularity is the codegen unit | CODEGEN-STENCIL.md §12 | mold rejected incremental linking partly *because it is not reproducible*, which this toolchain cannot accept. |
| A `stat` sweep over the declared source set, not `notify` | BUILD-AND-WATCH.md §1.2 | A general watcher is hard (Zed abandoned its own; Zig abandoned kqueue) and unnecessary when the cache keys already enumerate the input set. |
| One codegen unit per source module, in both profiles; no LTO | ARCHITECTURE.md §5 | Per-function objects lose colocated direct calls; a merged fixed count loses reuse; LTO re-derives an inlining decision the middle end took with an exact call graph. |
| `Str` is 24 bytes with a `base` pointer; `[T]` is 16 | VALUE-MODEL.md §3-4 | A uniform 16-byte shape would make `slice` allocate, contradicting `core/str`'s own contract. |
| Descriptors are folded at compile time and never reach a native artifact | VALUE-MODEL.md §9 | A runtime walker is an interpreter, defeats every memory attribute, and defeats DCE. |
| A context of zero-sized implementations costs nothing | VALUE-MODEL.md §8 | Nothing lost; `ctx_layouts` already records the layout statically. |
| `nsw`/`nuw` are never emitted | CODEGEN-LLVM.md §3.4 | Correct per SPEC 6.2, and it would replace a debuggable wrap with whatever the optimizer inferred. |
| `willreturn` only where the backend proved there is no cycle | CODEGEN-LLVM.md §3.6 | Reading *"a function `middle` proved terminates"* as `Purity::Pure` with no abort miscompiled every pure non-tail recursion at `default<O2>`: `memory(none)` + `willreturn` is `speculatable`, and LLVM hoisted the recursive call above its own base case. Also rejected: keeping the attribute for a loop, which licenses deleting a divergence SPEC 10.4 calls observable. |
| Cranelift pinned to the wasmtime 36 LTS — **reversed 2026-08-29**, with its subject | CODEGEN-STENCIL.md §13 | Tracking latest meant a monthly `identity()` change, which invalidated every cached object in every repository. The removal deleted the question: there is no version left to bump. |
| `backend-llvm` off by default; `backend-stencil` on | BUILD-AND-WATCH.md §2 | `cargo install buri` must not need a system LLVM. What is left needs nothing a machine able to link a native artifact does not already have, and adds nothing to the lockfile. |
| The stencil backend is the debug backend — **reversed 2026-08-29** | ARCHITECTURE.md §4, CODEGEN-STENCIL.md §13 | Parity was met — 997 of 997, the same six refusals, the same blocks live at exit — so Cranelift was removed: 38 transitive crates to 0, a clean release build in half the time, and x86-64 covered by writing the emitter rather than by keeping a second code generator. What lost, and is written down rather than repaired: a 1.38× debug runtime, and a `buri` 5.06 MB *larger* rather than smaller, because the stencil libraries the old binary dead-stripped are the code generator now (PERFORMANCE.md §5). |
| Cross-*linking* refused, explicitly; cross codegen supported | ARCHITECTURE.md §9 | The blocker is the host-only runtime archive rather than any backend, and naming that makes the fix a packaging problem rather than a compiler one. |
| `Arena` is accounting-only in v1 | MEMORY.md §7.2 | A real region-freeing arena needs a scoped-context construct the language does not have. |
| One symbol prefix, `buri_rt_`, for every runtime entry including the host ones | VALUE-MODEL.md §10 | A split `buri_rt_` / `buri_host_` makes "is this symbol the runtime's" a table lookup in the one place a compiler asks it per call site. |
| The v1 allocator is `malloc`-backed with no size classes | MEMORY.md §5.4 | Nothing observable differs — the header, the capacity, the reuse test and the *defined* `Alloc` cost model are identical — so the free lists can land later under a green suite instead of being co-developed with two backends. |
| The runtime archive is precompiled by `cli/build.rs`, not compiled on demand | BUILD-AND-WATCH.md §2.2 | On demand puts a `rustc` in the build loop and makes the archive hash depend on whatever `rustc` was on `PATH` at *use* time. |
| `Net::fetch` is cleartext `http://` only — **reversed 2026-08-30**, with its subject | `cli/runtime/http.rs`, `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | `https://` works, through `rustls` over the `ring` provider, checked against the host's trust anchors; a certificate that does not check out is a `NetError::Transport` naming what was wrong. What still stands is structural: `http.rs` cannot silently downgrade, because the scheme decides one thing — whether the socket is wrapped. The reversal costs 1.72 MiB in every binary this compiler produces, which is over the size budget CI carried and is re-stated there. A `net`-off toolchain keeps the refusal and its message names the feature. |
| Every step of a native `Net.fetch` is bounded, the **name lookup** included, and the lookup's bound is a thread the caller stops waiting on | `cli/runtime/http.rs`'s `DEADLINE`, `within` and `resolve`; `cli/runtime/tls.rs`'s `bound` | `connect_timeout` and the socket deadlines cover four of the five steps and nothing can cancel the fifth: `getaddrinfo` comes back when the resolver lets it, so a host whose DNS answers nothing had a `Net.fetch` that never returned. Leaving callers to bound it is what hung a CI job for an hour. It costs one thread per lookup that has a name in it and buys a client that returns on every network. It does not buy cancellation: the abandoned lookup finishes into a channel nobody is holding. |
| One bar, **two** admitted sets: the toolchain's and the runtime's | root `Cargo.toml`, BUILD-AND-WATCH.md §1.1, §1.1.1 | One list would have made "tokio is in the compiler" and "tokio is in every program the compiler produces" the same sentence. `libburi_rt.a` is linked into every native binary, so the runtime's set is a set strangers ship, and it carries a fourth clause the toolchain's does not: an **exact list**, asserted as an equality, so a fifth crate and a removal both fail a test. |
| The runtime's networking crates land **referenced by nothing** — amended five times; there are six crates now and five are reached | `cli/runtime/net.rs`, `manifest.toml`, `rt.rs`, `tls.rs` | Landing a crate with its first caller makes the archive's growth and the code that needed it one commit, and the growth is the irreversible part: `include_bytes!` puts the archive into every `buri` binary. Measured first instead — +24 bytes, because fat LTO drops what nothing reaches — and held there by a CI symbol-table check each later slice had to move deliberately. B6 linked the reactor (+185 424 bytes on aarch64-apple-darwin), C7 the TLS client and `ring` (+1 804 592), F4 `hyper`'s HTTP/2 server (+771 688), F7 `tungstenite`'s framing (+77 360). `quinn` is the only one still absent, and an `net-h3` archive is forty bytes *smaller* than one without it — the difference being a refusal string an h3 build has no use for. |
| The archive's feature list is a **file beside the archive**, and the refusal for a missing one is a **diagnostic before codegen** | `cli/build.rs`, `backend/runtime_native.rs`, `backend/mod.rs`, `docs/errors/networking-not-available.md` | A file wins over a `cargo:rustc-env` or reading `buri_rt_net_capabilities` out of the symbol table for the reason the baked digest is a file — one `OUT_DIR` written by one run of the build script, so a stale directory cannot pair one build's bytes with another's answer — and it generalises to `net-h3` as a second line rather than a second mechanism. The second half is what it is *for*: `Backend::missing_intrinsics` reports the `host.HostListen.*`/`HostSockets.*`/`HostTasks.*` family as missing when the archive has no `net`, before code generation, rather than as an unresolved `buri_rt_*` symbol from `cc`. |
| `net-h3` is **off by default**, and a toolchain without it **returns `.Err(Unsupported)`** rather than refusing the program | `cli/runtime/manifest.toml`, `cli/runtime/net.rs`'s `serves`, `cli/build.rs`, BUILD-AND-WATCH.md §1.1.3 | The default is opposite `net`'s because the payer is different: `net`'s crates are what any networked program needs, while `quinn` is what a program that **asked for HTTP/3** needs. The refusal is a value rather than a compile-time error because the protocol is a *field* on a plan rather than an operation, so refusing at compile time would refuse every program that mentions `serve` — including servers that only ever speak HTTP/1.1. An abort was the other alternative, and it turns a build-flag question into a dead process. |
| `quinn`'s crypto provider is pinned to **`ring`**, and CI greps for the other one | `cli/runtime/manifest.toml`, `cli/tests/ci.rs::the_runtime_archive_is_real` | `quinn`'s defaults are `rustls-aws-lc-rs` and `platform-verifier`, which would put a **second** cryptography implementation into every h3 binary and want `cmake` at build time. Both are off and `rustls-ring` is on, so the closed set grows by one crate rather than by a provider and its build tooling. The `aws_lc` tripwire in the archive script is what checks it. |
| `net-h3` is built on **one CI job**, and its archive is held to the **same size budget** | `.github/workflows/ci.yml`, `cli/tests/ci.rs::the_runtime_archive_is_real` | Nothing about the question is per-platform — `quinn` is portable Rust and what is asserted is a symbol table and a byte count — so four jobs would buy the same answer four times. It is the `x86_64` `test` leg's **last** step because it rebuilds the archive and relinks `buri`. The budget is shared rather than widened because the h3 archive is smaller; a separate, larger number would hide the growth the slice that first calls into `quinn` will cause. |
| Native suspension is a **carrier thread**, not a CPS transform | `cli/runtime/rt.rs`, design/native track B §0.1 | Buri machine code stays ordinary frame-threaded synchronous code and a suspending host call is one `park_on`. A native CPS/state-machine transform is larger than the two shapes `middle/mod.rs` and CODEGEN-LLVM.md have each already rejected, put together. **Amended (G3):** the run baton that originally paired with the carrier is gone. It was a staging device — it bought concurrency while parallelism waited, and let atomic reference counting land as its own priced slice. What replaces it is not a lock: values two carriers can both reach are marked, a marked block is counted atomically and never eligible for an in-place write, and `fan_out` is gated on the same mark, so the exclusion lives in the header word of the blocks a call touches. **Amended (B9):** the carrier thread has gone too. A task is a machine stack, a Buri data-stack list and one saved stack pointer; `park_on` polls and, on `Pending`, saves the stack and switches to the carrier. Nothing above `rt.rs` changed. A *carrier* is still a thread and there are still up to `MAX_CARRIERS` of them, because a task may block rather than park; what a task no longer costs is a thread while it **waits**. |
| The step ABI carries an **index word on every step**, not only on the keys that read one | `cli/runtime/list.rs`'s `StepEntry`, `backend/intrinsic_keys.rs` | `effect Tasks` promises the step its item's own index, and only the side driving the walk has one. Deriving it inside the entry thunk needs a base the state record does not carry, and stops being true the moment a scheduler hands elements out of order. Putting the word on `Tasks.parallel` alone costs *two* C signatures at a boundary whose whole value is that there is one. `list.mapCtxStep`'s thunk simply leaves the register unread. |
| `Tasks` is granted on `LINUX`, `MACOS` and `JS`, and **withheld from `WEB`** | `standard_library/mod.rs`, `cli/tests/reject/tasks_not_granted_on_web` | Not a backend limitation — `WEB` and `JS` share a code generator, so `Promise.all` would run there. `parallel` returns only when its last task has finished, and a page has an interface a wait is visible in. Every effect a page's host grants either answers instantly or suspends without holding the event loop. The callback-shaped task surface a page would want is the servers' slice, not this one. **Reversed 2026-09-06:** `core/tasks` gained `scope` and `spawn`, which is the surface that last sentence was waiting for, and the row now grants `Tasks` everywhere. The argument above was about `parallel` and it still holds of `parallel`; what it did not cover is that a page's own work — a socket, a retry, a timer — is a *task* and there was no other way to write one. `cli/tests/reject/tasks_not_granted_on_web` is gone with it. The last row of this table is the reversal in full. |
| `Tasks.parallel`'s body is in **`rt.rs`, behind `net`**, rather than beside the other list walks | `cli/runtime/rt.rs`, `backend/runtime_native.rs` | The body needs no reactor, so a featureless home would have compiled — and would have made `net_intrinsic`'s refusal, which names the `host.HostTasks.*` family, a lie until D4 made it true again. Putting it here means the first key that reached the refusal exercised it. **Amended:** the body is a fan-out onto the carrier pool rather than a loop, so the placement is now load-bearing — the scheduler needs the reactor the feature admits. |
| Whether a fan-out is legal is the **artifact's statement about itself**, made once at startup, not a word on the step boundary | `cli/runtime/lib.rs` §6, `backend/llvm/runtime.rs`'s `FRAMES_PER_CARRIER` | Two steps may run at once only where two steps may have live frames at once, which is a fact about where a Buri frame lives: a machine frame under LLVM, one shared `buri$stencil$stack` under the frame-threaded backend. `buri_rt_frames_are_per_carrier()` is one optional call in the emitted `main`, so silence is the safe answer and an entry point that forgets it is slow rather than wrong. The alternative, a lane count on `Extra::Step`, is the wrong altitude — the answer is the same at every call site — and widens a boundary two backends must agree on to carry a constant. B7 makes both backends state it, so the branch has one arm. |
| The fan-out is a **sliding window of 64 carriers**, not one carrier per item | `cli/runtime/rt.rs`'s `IN_FLIGHT` | A carrier is an OS thread with a 512 KiB stack, so the width is address space: 64 is 32 MiB per level of nesting. Unbounded matches `Promise.all` and asks the kernel for ten thousand threads on a ten-thousand-item list, which macOS refuses. The window costs the (n+1)-th task the wait for the first and costs the answer nothing, since the `[B]` is filled by index either way. B9 removes the bound rather than raising it — a parked task costs a stack switch and no thread. |
| `HostGrant::elsewhere_clause`'s **empty case is kept with no row using it** | `standard_library/mod.rs` | Deleting a branch because its first user graduated means rediscovering "build this for a platform that grants it:" with nothing after the colon on the day the next effect lands ahead of its runtime. Six lines and one test, against a diagnostic that reads like a compiler bug. |
| The carrier pool and the task table get **no `buri_rt_task_*` C ABI** beyond the one export that has a caller | `cli/runtime/rt.rs` §2 | An exported symbol is a contract both backends emit calls into, so writing one before a backend has a call to emit is a guess about a signature, and a wrong guess is a wrong answer at run time. `buri_rt_host_tasks_parallel` landed with both runtime-table rows and its caller in one commit (+544 bytes). `task_start`/`task_join` stay Rust-visible until a backend has a call to emit for them too. |
| `rustls` is admitted with **no crypto provider** — **reversed 2026-08-30**; the provider is `ring` | `cli/runtime/manifest.toml`, `cli/build.rs`, BUILD-AND-WATCH.md §1.1.2 | `aws-lc-rs` wants `cmake` at build time where `ring` wants a C compiler the toolchain already requires for the stencil library and for every link. The pure-Rust providers lose because `rustls-rustcrypto` says of itself that it is unaudited and not for production, and this archive is in every binary a stranger ships. The "turns degrades-rather-than-breaks into breaks" objection is answered rather than accepted: `cli/build.rs` **probes** for `cc` and falls back to `--no-default-features` with a `cargo:warning`, so a host without one gets a working toolchain, working `http://`, and an `https://` that refuses at run time naming the feature. A probe rather than a retry-on-failure, because retrying a failed compile would also hide a bug in the runtime's own TLS code. |
| Trust anchors come from the **host's PEM bundle**, with `SSL_CERT_FILE` overriding — and from no crate | `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | `webpki-roots` is a quarter-megabyte of data this repository would ship, pinning the trust set to a crate version rather than to the machine. `rustls-native-certs` reads the right thing and costs three transitive crates plus a link-time `Security.framework` on macOS, which a `staticlib` handed to `cc` cannot carry without every artifact's link line growing a flag. Reading `/etc/ssl/cert.pem` and its four Linux spellings is forty lines. It does not read the macOS keychain, which is what `SSL_CERT_FILE` is for — the spelling OpenSSL, `curl` and `git` already honour. Not cached across calls: a `OnceLock` would save a millisecond against a handshake costing tens, and would make "which roots" depend on when the first request happened. |
| The runtime crate's own unit tests are **run**, by a test in the toolchain's suite that shells out to `cargo test` | `cli/tests/native/runtime.rs`, `cli/build.rs` | `cli/runtime` is deliberately not a workspace member and its manifest is deliberately not named `Cargo.toml`, so `cargo test -p buri` could not reach inside it and no CI step did either — fifty-odd assertions about the float formatter, the UTF-16 comparison, the handle table and the allocator had been written and never executed. The `https://` slice needed a home for a test that starts a `rustls` server, and the only `rustls` here is inside that package, which the toolchain's crate cannot depend on without failing `dependencies_stay_behind_the_bar`. The path comes from `cargo:rustc-env=BURI_RT_PKG`, and the nested `cargo` gets the same environment scrubbing. |
| The runtime's cargo package is **assembled in `OUT_DIR`**; its manifest in the tree is `manifest.toml` | `cli/build.rs` §1, BUILD-AND-WATCH.md §2.2 | `cargo package` skips any subdirectory of a package that holds a `Cargo.toml` — unconditionally, ahead of `include`/`exclude` — so `cli/runtime/Cargo.toml` deleted the whole directory from the published crate and a registry `cargo install buri` failed with nothing to compile. `include = ["runtime/**"]` does not override it. Publishing `buri-rt` as its own crate remains available and is a registry decision with a release process attached; this one is a rename. It costs `cd cli/runtime && cargo build`, which no longer resolves — the build has one driver and it is `cli/build.rs`. |
| The archive is linked **only when the objects reference it**, and the question is asked of the objects rather than of the program | `build/link.rs`, `build/actions.rs::link_key_of` | A reachability query over `program.funcs` for intrinsic keys would have been wrong in the direction that fails a link: both entry points call `buri_rt_argv_init` and `buri_rt_flush` unconditionally, reference counting reaches `buri_rt_alloc`/`buri_rt_free`, a division emits `buri_rt_abort_div_zero`, and none is a `FuncKind::Intrinsic` anything could walk for. Asking the emitted objects for the `buri_rt_` prefix cannot go stale. **The measured consequence: the answer is `Linked` for every Buri program, hello world included, and no artifact got smaller** — dead-stripping is what decides size (370 288 bytes for `main() { .Ok(()) }` against a 6 035 480-byte archive). What it buys is the `link` key: an artifact that names no archive stops being relinked when the runtime changes. |
| The flake vendors **both** lockfiles into one directory, and asserts the archive it produced | `flake.nix`, BUILD-AND-WATCH.md §3.2 | Merging the *lockfiles* loses to nixpkgs' own hook: `cargoSetupPostPatchHook` diffs the vendor directory's `Cargo.lock` against `src`'s and aborts when they differ. A vendored `directory` source is a flat set of `name-version` directories, so merging *those* is a symlink loop and leaves `Cargo.lock` byte for byte. Leaving the gap open shipped for a day: `nix build` stayed green and produced a toolchain with no native backend, which is a different compiler under the same version number — hence `the_runtime_archive_is_real` in the derivation's `postBuild`. |
| The carrier entry ABI is **one signature in a third file**, fixed before its first caller | `backend/carrier.rs`, `backend/stencil/asm.rs`, `backend/llvm/emit.rs` | The opposite call from `rt.rs` §1's, and the asymmetry is the argument: that row refuses to export a *runtime* symbol before a backend has a call to emit, because only the runtime knows its shape. This symbol is the **backend's**, and two of them emit it under one name for one caller — if they disagree, whichever the scheduler calls first decides what the other meant, and nothing says so. So the shape is written down once, both emitters are built from it, and a unit test renders each side back out and diffs. What is *not* shared is what is behind the door: stencil takes a Buri data stack, LLVM takes none. |
| A carrier's Buri stack is **`mmap`ped per carrier**; `main` keeps the `__bss` block | `cli/runtime/memory.rs`, `backend/stencil/asm.rs` | One 64 MiB `__bss` block with one `PROT_NONE` guard is right for one thread and wrong for two: a second carrier's frames would land in the first's, and a runaway recursion would silently overwrite somebody else's locals instead of faulting at the guard. A TLS `__bss` array multiplies 65 MiB of address space by every thread a program starts and cannot be `mprotect`ed once. `main` is left alone, so a program that never starts a carrier makes no new system call. **Amended (G6):** on release the mapping is kept and the pages are not — everything above a 256 KiB retained prefix goes back to the kernel when a block goes idle, which is 48 MiB of resident set on one carrier and 127 MiB across four. A watermark word makes a shallow entry cost a load instead of a system call, with a floor of one decommit per 1024 releases under it. Measured: 0.004 µs → 0.014 µs per entry, against 8.4 µs for the decommit. **Amended (B9):** per *task*, and there are two mappings — the Buri data stack and the task's machine stack. Both are decommitted when idle and both keep 256 KiB, at opposite ends, because a data stack grows up and a machine stack grows down. A data stack is acquired once per **entry into Buri code**, so G6's watermark matters; a machine stack once per **task**, which is rare enough to decommit every time into a pool capped at sixty-four. |
| `TestTasks.parallel` drives the **same closure trampoline** the real one drives, rather than being a Buri loop — **reason amended 2026-08-30** | `sources/host_testing.buri`, `backend/intrinsic_keys.rs`, `cli/runtime/testing.rs` | The original reason — a method body has no name for the caller's context — is gone, because the context is a named parameter now. It stands on the stronger one: **the order is the runtime's**. A permutation of `0..n` with a fault plan and a call log is not something a Buri body can choose, and going through `step_call` puts the double on the boundary the program will ship on with exactly one thing changed. It costs a third `Extra::Step` key and a `self` that is `Arg::Scalar` where `host.HostTasks.parallel`'s is `Arg::Dropped`, because the runtime has to ask the handle which order this run schedules in. |
| `Self` is the **implementing type everywhere**, and a callback meant to receive the caller's context takes a named `ctx` parameter instead | `sources/effect.buri`, `cli/src/docs/language/effects.md` §10.6, `semantics/expressions.rs`'s `implementing_ty` | `Tasks.parallel` was declared `f: fn(Self, Int, A) => B` and documented as handing the step "the full context", and those are two different values, so a step reading `c.nowMillis()` answered `0` natively and *threw* on JavaScript. **Redefining `Self`-inside-a-callback to mean the caller's context lost** on SPEC 10.9: an effect is an ordinary interface anyone may implement, and a parameter typed "the caller's context" has a type no `impl` can name, so no implementation written in Buri could ever call its own callback. Naming it costs one parameter and one repeated argument at one call site, and buys a front end with no special case and a nine-line Buri `SerialTasks` that honours the promise. The native cost is nothing: `ctx` is `Arg::Dropped` in both tables. |
| `TestTasks.parallel` drives the **same closure trampoline** the real one drives, rather than being a Buri loop | `sources/host_testing.buri`, `backend/intrinsic_keys.rs`, `cli/runtime/testing.rs` | A Buri body was written first and cannot be right: the step is handed the *caller's context* and a method body has no name for one, so what a body passes is its own receiver — a different value of a different width, which natively is a shifted argument list rather than a diagnostic. |
| A **seed is the order's own number**, not a generator's | `cli/runtime/testing.rs`, `backend/js/runtime.js` | `n!` orders, numbered from zero in lexicographic order, read out through the factorial number system. A shuffle is not invertible, so a report naming a shuffle's seed could only be replayed by re-running the same generator on the same platform — and the two backends here are Rust and JavaScript. This way `everyOrder`'s `k`th run and `seed(k)` are the same sentence, and a content-derived seed is legal at every length because ranks wrap. |
| `everyOrder` reruns the body by a **self tail call the middle end emits**, not by a loop where blocks are called from | `middle/monomorphize.rs`, both runtime tables | Blocks are called from three places — two hand-written machine-code entry points and a string of JavaScript — so a loop there is three implementations of one rule, one of them a relocation golden. `ExprKind::Loop` rebinds a function's parameters and a `test` block has no parameters, so the honest spelling of *run it again* is the call the language already has, which `tail_calls` turns into the jump. |
| A task the fault plan fails **ends the block** | `sources/host_testing.buri`, `cli/tests/failing/every_order/` | `Tasks.parallel` answers `[B]` and every `B` comes from the closure, so a double that refuses a task cannot answer and cannot skip and still fill the list. Ending the run is what a task that died would do for real, so the fault carries a **reason** where `FsFault` carries an `IoError`.
