# The decision index

Everything in `design/native/` is decided. This file is the index: one row per
decision close enough to be worth arguing, the document that argues it in full,
and the alternative that lost. Where a row and its document disagree, the
document is right — this is a table of contents, not a second source.

Nothing here is open. A reversed decision is reversed in the document that made
it, and the reversal is recorded there rather than deleted.

| Decision | Where | The alternative that lost |
|---|---|---|
| **A `core/host` name is checked against the entry whose body it sits in** | `semantics/resolve.rs` `module_platforms`, `build/build-files.md` | The rule was per *target*: `main.buri` was checked against every platform the `outputs` name. With two entries in one file that refuses a correct program — a page's `Ui: host.ui` fails on the worker's behalf and the worker's `Environment: host.env` fails on the page's. Checking the reachable set instead is the same answer and needs a whole-program walk in a phase that has not run; an entry builds its own context and a context may be built nowhere else, so the enclosing entry is the whole of the surface that varies. A name outside an entry's body — a helper, a top-level import — is still checked against every output, because any of them may reach it. |
| **`core/host`'s exports are no longer subset per platform; the two report sites are the whole rule** | `semantics/resolve.rs` | The removed pass deleted the withheld names from `core/host`'s export table, so a page had no `fs` to name at all. It cannot survive several entries: a build of the page would delete the names the worker's entry binds. Both diagnostics already fired *before* the lookup and bound the name anyway, so nothing in the corpus changed. |
| **A second entry's artifact is named after its entry** | `build/actions.rs` `artifact_path` | Two outputs of one binary otherwise write one path. `main` keeps the directory's name, so nothing written before entries were nameable moves; `artifact_name` still overrides. |
| **`buri run` does not run a worker** | `commands/run.rs`, `cli/run.md` | `run` starts a program. A worker is called by its platform, once per request, so there is nothing to start; a binary declaring a page and a worker runs the page, and one declaring a worker and nothing else is refused with that sentence and told to build it instead. Handing the module to a JavaScript runtime was the alternative and is worse than useless: it exits 0 having started nothing. |
| **The entry name is in every cache key an output reaches** | `build/cache.rs`, `build/actions.rs` | Without it two outputs of one binary share a key, and the artifact for one entry is served for the other's. The entry is the root dead-code elimination walks from and the body the platform check is asked on behalf of, so the same sources produce different bytes. |
| **A worker's `Request` and `Response` are `core/effect`'s** | `semantics/resolve.rs` `check_fetch_entry` | A pair of the worker's own would be a second HTTP message type, and `Network.fetch` already speaks these. It also keeps `CLOUDFLARE_WORKER` free of any dependency on `ui/web`. |
| **`shell` answers the document, and `http.html` answers the response** | `sources/web.buri`, `sources/http.buri` | The proposal's own line is `http.html(ctx, web.shell(...))`, so `shell` producing a `Response` would make that line ill-typed and give `ui/web` a second opinion about status codes and headers. A document is a string; turning one into an HTTP message is `core/net/http`'s job, and `html` is one line beside `json`. |
| **`render` takes the tree and no context** | `sources/web.buri` | The proposal writes `web.render(node)`. It is sound rather than merely short: every constructor in `ui/node` is unbounded in `C`, so nothing inside a tree can act on a context, and a handler is not called at all when what comes back is text. The runtime passes `null` where `mount` passes the caller's context. |
| **`resume` takes the tree, and adopts the markup rather than rendering it** | `sources/web.buri`, `backend/js/runtime.js` | The proposal writes `web.resume(ctx)` with no tree, and that shape shipped first: it read the embedded state and left the document alone. It cannot make a page work — a handler lives in a `Node`, so a resume with no tree has nothing to attach and a server-rendered button does nothing, which is the whole reason a page is shipped at all. So `resume(ctx, root)` runs the one renderer against the document that arrived: `$tree_element` and `$tree_text` answer with the node already sitting there, markers are inserted where the walk reaches, and what the pass adds is the listeners and the computations. Rejected: a second renderer that walks markup, which is a second thing to be right; and mounting over the top, which throws away exactly what the server sent. `web.state(ctx)` reads the embedded state before the resume rather than after it, because the tree is built out of it. A tree the markup does not match is `.Err` naming what was wanted and what was there — guessing would leave the reader looking at both answers. |
| **The proposal's `state.toJson()` is `state.toJson(ctx)`, and a page's text is prepared outside the closure** | `sources/json.buri`, `sources/ui_prop.buri`, `guides/websites.md` | Both are forced by signatures that predate the feature and neither is `ui/web`'s to change. `ToJson::toJson<C: Allocator>(self, ctx: C)` names an allocator because rendering allocates, and a worker has one. A `Computed` prop holds a `fn(Scope) => T`: a `Scope` reads the graph and grants nothing else, and a closure may not capture a capability (SPEC 10.6), so a route's closure cannot turn an interpolation into a `Str`. What varies is prepared where there is a context and captured, which is what the worked page does and what the guide says in the sentence beside it. |
| **The state crosses as JSON text in an inert `<script>`** | `sources/web.buri` | A `<script type="application/json">` is neither run nor rendered, and the page reads it by id. Every `<` in it is escaped as a JSON `<`, which is why a state holding `</script>` closes nothing. The alternative — a global assignment in a real script — is executable text built from user data. |
| **`Location` answers a cell, not a string** | `sources/ui_effect.buri` | Every identifier in `ui/effect` is an `Int`, because that module is the boundary with a runtime holding one graph of untyped cells. A `Str` would make navigation invisible: `web.route` wraps the cell in a `Prop`, so a computation that read the path re-runs when the reader navigates, and `web.path` reads the same cell once. |
| **A worker's grants are not widened for the address bar** | `standard_library/mod.rs` `HOST_GRANTS` | `Location` is `WEB` alone. A worker is handed a request and reads `Request.path`, which is a field of a value and no authority — so there is nothing for a grant to buy, and the case's negative twin is a `fetch` that asks for one. |
| **The graph a server-side render registers is dropped with the answer** | `backend/js/runtime.js` `$ui_web_render` | A worker's module state outlives the request, and a `computed` node registers a cell whether or not anything will ever read it again. The render truncates the graph back to the length it had, which is right because the tree is thrown away with the HTML. |
| **`ui/web` is JavaScript's alone** | `backend/runtime_table.rs`, `tests/native/conformance.rs` | Both platforms a website is built for are JavaScript, and a native artifact has no document under it. So there are no native runtime entries, a native build reaching one stops at code generation naming the operation, and the conformance package says `platforms: [JS]` with that reason. |
| **Only HTML's own empty elements self-close in rendered markup** | `backend/js/runtime.js` `$dom_markup`, `sources/web.buri` | `<div />` is an *opening* tag to an HTML parser: everything after it lands inside. So an empty region swallowed the rest of the page, and a resume onto that markup saw a tree it did not match — a whole website broken by one `column([], [])`. `img`, `input` and `hr` keep the slash, because a closing tag for one of those is markup a browser refuses to nest. `ui/testing`'s `markup()` moved with it, since there is one serializer and the conformance package asserts the two renderers agree. A `textarea` came with it: what is typed into one is its text, not a `value` attribute. |
| **A resume refuses a shape and writes a value** | `runtime.js` `$adopt_claim`, `sources/web.buri`, `guides/websites.md` | An element that is missing, renamed, or unaccounted for is `.Err` naming what was wanted and what was there. A run of text or an attribute that differs is written in place, because the numbers a page renders come from a state that is allowed to have moved on. The rule was written down for text and not for attributes; it is the same rule and now says so. A **second** `resume` on one document is refused like any other disagreement — the first pass left markers the server never wrote — and the module says to resume once. |
| **`shell` writes the path it rendered for, and `resume` checks the address before the shape** | `sources/web.buri`, `runtime.js` `$ui_web_resume`, `guides/websites.md` | Two routes that render the same *shape* — a heading and a paragraph, say — adopt each other's markup and the walk finds nothing wrong, so a page resumed at the wrong address ends up showing one route's markup with the other route's handlers on it, silently. `shell` gained a `path` parameter and writes it as `data-path` on the state script it already emits; `resume` compares it against `location.pathname` first and answers `.Err` naming both. Rejected: comparing what the tree renders, which is the thing that cannot tell these apart. A query string and a fragment are not compared, because neither is part of a path — `Request.path` and `location.pathname` both leave them out, so one page does not become two when a reader arrives from a campaign link. Markup no `shell` wrote has no `data-path` and keeps the shape check alone. `resume` stays `C: Ui` rather than gaining `Location`: the address is read to check a precondition and never handed to the program, and `Ui` is `WEB` alone, so a resume is already only reachable where there is an address bar — requiring the grant would tax every page that does not route. |
| **A worker's tree holds no `field` and no `toggle`** | `sources/ui_node.buri`, `guides/websites.md` | Both bind to a `Signal`, and `signal` names `Ui`, which is `WEB` alone. So a form cannot be server-rendered today. Recorded rather than fixed: making a `Signal` without `Ui` is a change to what a cell *is*, not to `ui/web`, and the guide says what to do instead. |
| **A control's styles are a parameter on `button`, `link`, `field` and `toggle` — not a `styled(styles, node)` wrapper — and the sheet opens with a reset for the elements the program builds** | `sources/ui_node.buri`, `backend/js/runtime.js` `$tree_render`, `semantics/styles.rs` `Reset` | The wrapper's one argument is that it keeps every call site compiling. It cannot pay for itself anywhere else: there is one renderer and it builds an element from the node it is standing on, so a wrapper would have to reach into the node it holds and hand the styles down — the parameter, with a variant in front of it, in `$tree_render`, in `web.render`'s markup and in `describe`'s scene document alike. Every call site in the repository moved instead. A field's and a toggle's styles land on the input rather than the label around it, because the input is what a browser focuses and disables. The reset is element selectors inside `:where()`, so it weighs nothing in the cascade and every atomic class beats it whatever order they land in; it is emitted per element the artifact can actually build, which is a walk over `NodeKind` literals beside the two that already decide the inline tier and the theme half. A toggle's checkbox is left out of it: `appearance: none` erases the tick and this vocabulary has nothing to draw a new one with. |
| **A heading's level is its outline position, and its size and weight are its styles** | `sources/ui_node.buri`, `backend/js/runtime.js` `$tree_render`, `semantics/styles.rs` `Reset` | `heading` took no `[Style]` and rendered an unclassed `<h1>`–`<h6>`, so the browser's user-agent sheet decided the type and `describe` — which *did* apply a per-level size and weight — disagreed with the browser about the same tree. The metrics are gone rather than re-asserted as element rules: a per-level `font-size` is a declaration on the element, so it beats an ancestor's inherited one and the level is a size again, which is the design this vocabulary rejected. `heading(level, styles, content)` instead, beside the four controls, with `:where(h1,h2,h3,h4,h5,h6){font-size:inherit;font-weight:inherit;margin:0}` in the same reset they opened. The margin is the half nothing else could reach: it is not inherited, so no ancestor's style touches it, and the scene document the headless painter reads has no counterpart for one — which is exactly where the two renderers laid the same tree out differently. |
| **The outputs of one target share one diagnostic sink** | `commands/build.rs` | Two outputs are two compilations of one `main.buri`, so a helper that would not typecheck was reported once per artifact — against the repository's own "one mistake reads as one mistake". `Diagnostics` already deduplicates by span and message; it just needed to outlive the loop. |
| Reference counting, not a GC | MEMORY.md §3 | A tracing GC needs statepoints or conservative scanning. Statepoints contradict CODEGEN-LLVM.md §0's second instruction; conservative scanning makes the heap data-dependent and irreproducible. |
| `Checked` is bounded by the numbers the *backend* has | VALUE-MODEL.md §11, SPEC §6.2.2 | A native backend that also stopped at 2^53 shipped for a wave and was reversed: it makes `Checked` useless on `I64` natively, and buys portability of a result nobody should branch on. |
| `Str` slicing keeps its parent buffer alive, and that is not a language question | MEMORY.md §5.3, §6 | Copying above a ratio makes `slice` name `Allocator` and retracts `core/str`'s purity claim. Copying on proven retention is a real analysis for a case that is hard to detect, and it stays available precisely because it is not language-visible. |
| Exactly one supported LLVM at a time, tracking the latest both inkwell and the flake carry | CODEGEN-LLVM.md §8.1–8.3 | "The flake leads" forbids a bump the backend needs. "The backend leads" prices a nixpkgs bump — which moves `cargo`, `bun` and `elan` — into a routine chore. Multi-version support is refused permanently: two LLVMs means one attribute encoded two ways. |
| No arena per `Allocator` scope | MEMORY.md §4 | `Allocator` is a propagating bound and `Region` is a value; there is no scope to hang an arena on. |
| The middle end owns tail-call elimination; no backend uses its own | CODEGEN-LLVM.md §5 | `musttail`/`tailcc` and `return_call` are both viral, both incompatible with a C-ABI runtime, and both unnecessary once the tail-call graph is a DAG. |
| A promoted loop variable is read from its register inside the promotion's region and from its frame slot outside it | CODEGEN-STENCIL.md §2, `backend/stencil/jit.rs`'s `Fn2::loc` | One answer per value — "it is in a register", everywhere in the function — is what the promotion shipped as, and it holds only where the region says nothing clobbers the file. A `Bool` walk that recursed from an `else if` *and* from a `&&` read its index on both sides of a `charAt`: the register came back holding whatever the call left, the second arm handed back a nonsense index, and the walk answered `true` for every input (buri-lang/buri#47). Rejected: refusing to promote a variable that any block outside the region reads. It is correct, and it gives up the loop register for every `all`-shaped walk — the recursion an immutable language writes most often. |
| Neither linker links incrementally; recompile granularity is the codegen unit | CODEGEN-STENCIL.md §12 | mold rejected incremental linking partly *because it is not reproducible*, which this toolchain cannot accept. |
| A `stat` sweep over the declared source set, not `notify` | BUILD-AND-WATCH.md §1.2 | A general watcher is hard (Zed abandoned its own; Zig abandoned kqueue) and unnecessary when the cache keys already enumerate the input set. |
| One codegen unit per source module, in both profiles; no LTO | ARCHITECTURE.md §5 | Per-function objects lose colocated direct calls; a merged fixed count loses reuse; LTO re-derives an inlining decision the middle end took with an exact call graph. |
| `Str` is 24 bytes with a `base` pointer; `[T]` is 16 | VALUE-MODEL.md §3-4 | A uniform 16-byte shape would make `slice` allocate, contradicting `core/str`'s own contract. |
| Descriptors are folded at compile time and never reach a native artifact | VALUE-MODEL.md §9 | A runtime walker is an interpreter, defeats every memory attribute, and defeats DCE. |
| A context of zero-sized implementations costs nothing | VALUE-MODEL.md §8 | Nothing lost; `ctx_layouts` already records the layout statically. |
| `nsw`/`nuw` are never emitted | CODEGEN-LLVM.md §3.4 | Correct per SPEC 6.2, and it would replace a debuggable wrap with whatever the optimizer inferred. |
| `willreturn` only where the backend proved there is no cycle | CODEGEN-LLVM.md §3.6 | Reading *"a function `middle` proved terminates"* as `Purity::Pure` with no abort miscompiled every pure non-tail recursion at `default<O2>`: `memory(none)` + `willreturn` is `speculatable`, and LLVM hoisted the recursive call above its own base case. Also rejected: keeping the attribute for a loop, which licenses deleting a divergence SPEC 10.4 calls observable. |
| Cranelift pinned to the wasmtime 36 LTS — **reversed 2026-08-29**, with its subject | CODEGEN-STENCIL.md §13 | Tracking latest meant a monthly `identity()` change, which invalidated every cached object in every repository. The removal deleted the question: there is no version left to bump. |
| `backend-llvm` off by default; `backend-stencil` on | BUILD-AND-WATCH.md §2 | `cargo install buri` must not need a system LLVM. What is left needs nothing a machine able to link a native artifact does not already have, and adds nothing to the lockfile. |
| The stencil backend is the debug backend — **reversed 2026-08-29** | ARCHITECTURE.md §4, CODEGEN-STENCIL.md §13 | Parity was met — 997 of 997, the same six refusals, the same blocks live at exit — so Cranelift was removed: 38 transitive crates to 0, a clean release build in half the time, and x86-64 covered by writing the emitter rather than by keeping a second code generator. What lost, and is written down rather than repaired: a 1.38× debug runtime, and a `buri` 5.06 MB *larger* rather than smaller, because the stencil libraries the old binary dead-stripped are the code generator now (PERFORMANCE.md §5). |
| Cross-*linking* refused, explicitly; cross codegen supported | ARCHITECTURE.md §9 | The blocker is the host-only runtime archive rather than any backend, and naming that makes the fix a packaging problem rather than a compiler one. |
| `Arena` is accounting-only in v1 | MEMORY.md §7.2 | A real region-freeing arena needs a scoped-context construct the language does not have. |
| One symbol prefix, `buri_rt_`, for every runtime entry including the host ones | VALUE-MODEL.md §10 | A split `buri_rt_` / `buri_host_` makes "is this symbol the runtime's" a table lookup in the one place a compiler asks it per call site. |
| The v1 allocator is `malloc`-backed with no size classes | MEMORY.md §5.4 | Nothing observable differs — the header, the capacity, the reuse test and the *defined* `Allocator` cost model are identical — so the free lists can land later under a green suite instead of being co-developed with two backends. |
| The runtime archive is precompiled by `cli/build.rs`, not compiled on demand | BUILD-AND-WATCH.md §2.2 | On demand puts a `rustc` in the build loop and makes the archive hash depend on whatever `rustc` was on `PATH` at *use* time. |
| `Network::fetch` is cleartext `http://` only — **reversed 2026-08-30**, with its subject | `cli/runtime/http.rs`, `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | `https://` works, through `rustls` over the `ring` provider, checked against the host's trust anchors; a certificate that does not check out is a `NetError::Transport` naming what was wrong. What still stands is structural: `http.rs` cannot silently downgrade, because the scheme decides one thing — whether the socket is wrapped. The reversal costs 1.72 MiB in every binary this compiler produces, which is over the size budget CI carried and is re-stated there. A `net`-off toolchain keeps the refusal and its message names the feature. |
| Every step of a native `Network.fetch` is bounded, the **name lookup** included, and the lookup's bound is a thread the caller stops waiting on | `cli/runtime/http.rs`'s `DEADLINE`, `within` and `resolve`; `cli/runtime/tls.rs`'s `bound` | `connect_timeout` and the socket deadlines cover four of the five steps and nothing can cancel the fifth: `getaddrinfo` comes back when the resolver lets it, so a host whose DNS answers nothing had a `Network.fetch` that never returned. Leaving callers to bound it is what hung a CI job for an hour. It costs one thread per lookup that has a name in it and buys a client that returns on every network. It does not buy cancellation: the abandoned lookup finishes into a channel nobody is holding. |
| One bar, **two** admitted sets: the toolchain's and the runtime's | root `Cargo.toml`, BUILD-AND-WATCH.md §1.1, §1.1.1 | One list would have made "tokio is in the compiler" and "tokio is in every program the compiler produces" the same sentence. `libburi_rt.a` is linked into every native binary, so the runtime's set is a set strangers ship, and it carries a fourth clause the toolchain's does not: an **exact list**, asserted as an equality, so a fifth crate and a removal both fail a test. |
| The runtime's networking crates land **referenced by nothing** — amended five times; there are six crates now and five are reached | `cli/runtime/net.rs`, `manifest.toml`, `rt.rs`, `tls.rs` | Landing a crate with its first caller makes the archive's growth and the code that needed it one commit, and the growth is the irreversible part: `include_bytes!` puts the archive into every `buri` binary. Measured first instead — +24 bytes, because fat LTO drops what nothing reaches — and held there by a CI symbol-table check each later slice had to move deliberately. B6 linked the reactor (+185 424 bytes on aarch64-apple-darwin), C7 the TLS client and `ring` (+1 804 592), F4 `hyper`'s HTTP/2 server (+771 688), F7 `tungstenite`'s framing (+77 360). `quinn` is the only one still absent, and an `net-h3` archive costs 4 544 bytes over one without it — it was forty bytes *smaller* under fat LTO, and the thin-LTO row below is what moved that. |
| The archive's feature list is a **file beside the archive**, and the refusal for a missing one is a **diagnostic before codegen** | `cli/build.rs`, `backend/runtime_native.rs`, `backend/mod.rs`, `docs/errors/networking-not-available.md` | A file wins over a `cargo:rustc-env` or reading `buri_rt_net_capabilities` out of the symbol table for the reason the baked digest is a file — one `OUT_DIR` written by one run of the build script, so a stale directory cannot pair one build's bytes with another's answer — and it generalises to `net-h3` as a second line rather than a second mechanism. The second half is what it is *for*: `Backend::missing_intrinsics` reports the `host.HostListen.*`/`HostSockets.*`/`HostTasks.*` family as missing when the archive has no `net`, before code generation, rather than as an unresolved `buri_rt_*` symbol from `cc`. |
| `net-h3` is **off by default**, and a toolchain without it **returns `.Err(Unsupported)`** rather than refusing the program | `cli/runtime/manifest.toml`, `cli/runtime/net.rs`'s `serves`, `cli/build.rs`, BUILD-AND-WATCH.md §1.1.3 | The default is opposite `net`'s because the payer is different: `net`'s crates are what any networked program needs, while `quinn` is what a program that **asked for HTTP/3** needs. The refusal is a value rather than a compile-time error because the protocol is a *field* on a plan rather than an operation, so refusing at compile time would refuse every program that mentions `serve` — including servers that only ever speak HTTP/1.1. An abort was the other alternative, and it turns a build-flag question into a dead process. |
| `quinn`'s crypto provider is pinned to **`ring`**, and CI greps for the other one | `cli/runtime/manifest.toml`, `cli/tests/ci.rs::the_runtime_archive_is_real` | `quinn`'s defaults are `rustls-aws-lc-rs` and `platform-verifier`, which would put a **second** cryptography implementation into every h3 binary and want `cmake` at build time. Both are off and `rustls-ring` is on, so the closed set grows by one crate rather than by a provider and its build tooling. The `aws_lc` tripwire in the archive script is what checks it. |
| `net-h3` is built on **one CI job**, and its archive is held to the **same size budget** | `.github/workflows/ci.yml`, `cli/tests/ci.rs::the_runtime_archive_is_real` | Nothing about the question is per-platform — `quinn` is portable Rust and what is asserted is a symbol table and a byte count — so four jobs would buy the same answer four times. It is the `x86_64` `test` leg's **last** step because it rebuilds the archive and relinks `buri`. The budget is shared rather than widened because the h3 archive is smaller; a separate, larger number would hide the growth the slice that first calls into `quinn` will cause. |
| Native suspension is a **carrier thread**, not a CPS transform | `cli/runtime/rt.rs`, design/native track B §0.1 | Buri machine code stays ordinary frame-threaded synchronous code and a suspending host call is one `park_on`. A native CPS/state-machine transform is larger than the two shapes `middle/mod.rs` and CODEGEN-LLVM.md have each already rejected, put together. **Amended (G3):** the run baton that originally paired with the carrier is gone. It was a staging device — it bought concurrency while parallelism waited, and let atomic reference counting land as its own priced slice. What replaces it is not a lock: values two carriers can both reach are marked, a marked block is counted atomically and never eligible for an in-place write, and `fan_out` is gated on the same mark, so the exclusion lives in the header word of the blocks a call touches. **Amended (B9):** the carrier thread has gone too. A task is a machine stack, a Buri data-stack list and one saved stack pointer; `park_on` polls and, on `Pending`, saves the stack and switches to the carrier. Nothing above `rt.rs` changed. A *carrier* is still a thread and there are still up to `MAX_CARRIERS` of them, because a task may block rather than park; what a task no longer costs is a thread while it **waits**. |
| The step ABI carries an **index word on every step**, not only on the keys that read one | `cli/runtime/list.rs`'s `StepEntry`, `backend/intrinsic_keys.rs` | `effect Tasks` promises the step its item's own index, and only the side driving the walk has one. Deriving it inside the entry thunk needs a base the state record does not carry, and stops being true the moment a scheduler hands elements out of order. Putting the word on `Tasks.parallel` alone costs *two* C signatures at a boundary whose whole value is that there is one. `list.mapCtxStep`'s thunk simply leaves the register unread. |
| `Tasks` is granted on `LINUX`, `MACOS` and `JS`, and **withheld from `WEB`** | `standard_library/mod.rs`, `cli/tests/reject/tasks_not_granted_on_web` | Not a backend limitation — `WEB` and `JS` share a code generator, so `Promise.all` would run there. `parallel` returns only when its last task has finished, and a page has an interface a wait is visible in. Every effect a page's host grants either answers instantly or suspends without holding the event loop. The callback-shaped task surface a page would want is the servers' slice, not this one. **Reversed 2026-09-06:** `core/tasks` gained `scope` and `spawn`, which is the surface that last sentence was waiting for, and the row now grants `Tasks` everywhere. The argument above was about `parallel` and it still holds of `parallel`; what it did not cover is that a page's own work — a socket, a retry, a timer — is a *task* and there was no other way to write one. `cli/tests/reject/tasks_not_granted_on_web` is gone with it. The last row of this table is the reversal in full. |
| `Tasks.parallel`'s body is in **`rt.rs`, behind `net`**, rather than beside the other list walks | `cli/runtime/rt.rs`, `backend/runtime_native.rs` | The body needs no reactor, so a featureless home would have compiled — and would have made `net_intrinsic`'s refusal, which names the `host.HostTasks.*` family, a lie until D4 made it true again.
