# The decision index

Everything in `design/native/` is decided. This file is the index: one row per
decision close enough to be worth arguing, the document that argues it in full,
and the alternative that lost. Where a row and its document disagree, the
document is right — this is a table of contents, not a second source.

Nothing here is open. A reversed decision is reversed in the document that made
it, and the reversal is recorded there rather than deleted.

| Decision | Where | The alternative that lost |
|---|---|---|
| **A diagnostic code is `[subject-]adjective-thing` or `subject-relation`, from one closed vocabulary** | `crates/docs/src/docs/reference/errors/README.md`'s "Naming a code", `documentation/errors.rs`, `documentation/lints.rs` | `unknown-`, `missing-`, `duplicate-`, `invalid-`, `untyped-` and `misplaced-` go before the thing, `-not-<kind>`, `-outside-<place>`, `-mismatch`, `-count`, `-unavailable` and `-unsupported` after the subject, with no articles, no possessives, no `wrong` and no abbreviations but `ctx` and `impl`. It renamed 165 codes and merged 16 groups of near-duplicates into one code each, such as `module-not-found` and `no-such-module` into `unknown-module`. **Keeping each code's name as written lost**: four spellings of "doesn't exist" (`no-such-`, `unresolved-`, `not-found`, `unknown-`) and five of "given twice" meant a reader couldn't guess a code from its message or grep for a family. **Aliases for the old names lost too**: a lint code is a `REPO.buri` field, and an alias would make two fields mean one rule. |
| **An entry takes its platform's host, and the CLI builds it in a wrapper exported under the entry's symbol** | `middle/monomorphize.rs` `entry`, `semantics/resolve.rs` `check_program_entry`, `crates/stdlib/src/platforms/*/platform.buri` | `main(host: NativeHost)` is called by nobody who could pass one, so monomorphization builds a function of no parameters that constructs the host — every field a field-less struct from `platform/host` — calls the entry with it, and takes the entry's symbol, while the entry takes a suffixed one. Every backend keeps calling a host-less entry and none of them knows a host exists. **Building the host in each backend's epilogue lost**: three epilogues to keep in step, and a host field the program never binds would still have been constructed in runtime code. **A platform building `ctx` from the entry's declared bound lost** to the design: it is a second bound system. |
| **`platform/effect`, `platform/host` and `platform/effect/testing` keep the runtime keys `effect`, `host` and `host_testing`** | `middle/monomorphize.rs` `runtime_module_key` | The key is the module path minus `core/`, and every runtime table, `runtime.js` and `middle::rc::suspends` is written against it. Three modules moving is no reason for any of them to move, so the three new paths are aliased to the old first segments in the one function that mints a key. **Renaming every key lost**: hundreds of rows across four runtimes and the `suspends` list, for no change in behaviour. |
| **`core/effect` and `core/host/testing` are retired, not aliased** | `standard_library/mod.rs` `RETIRED` | Importing either is `retired-module` naming the new path. An alias would be one module with two names, and the two imports would only look like different modules. |
| **`core/platforms/testing/state` keeps a whole `T` per handle with its release glue, behind one re-entrant lock** | `cli/runtime/testing.rs`'s state section | `core/actor`'s one-element `[Carried<T>]` blocks. **The block lost** because the runtime can't free one without glue, so a state nobody drops would fail the exit heap check; `Extra::Owned`'s release lets the runtime give every value back at exit, as `ui.rs`'s signals do. **A lock per state lost** because an `update` may update another state, and two threads nesting two states in opposite orders would deadlock; one lock, re-entrant per thread, can't. The keys aren't in `crosses_tasks`: a handle reaches another thread only through a key that is, which already counts every block atomically. A state used inside its own `update` stops the program rather than handing out a value `f` already holds. |
| **A size is the whole box, and the sheet's reset says so once for every element** | `semantics/styles.rs`'s `Reset` | `box-sizing: border-box` on `*`, so a `Width` counts its padding and border inside it. **Leaving CSS's `content-box` lost**: the headless painter measures the border box (taffy's own default), so a padded, bordered child laid out one way in a golden and another in a browser, and every design system this vocabulary is aimed at is written against `border-box`. **A `BoxSizing` property lost** too — it would be one more of the fifty for a value no program would ever write the other way. |
| **A container that names no `Layout` is a flex column, written in the reset rather than as a class on every element** | `semantics/styles.rs`'s `Reset` | `Layout`'s doc says a container with no `Layout` stacks its children downwards, and the painter has laid one out that way all along; in a browser it was `display:block`, where `AlignMain` and `AlignCross` are computed and inert. **Emitting a `lay-col` class on every container lost**: it changes the class list of every element in every golden, and it would put `display:flex` on `<table>` and `<tr>`, whose own table layout is what the scene document mirrors. **Refusing `Align*` without a `Layout` lost** because it contradicts the documented default. The four table elements are the reset rule's only exception. |
| **The platform's focus outline is taken away from the classes that draw a ring, not from `:focus-visible` at large** | `semantics/styles.rs`'s `focus_ring` | A browser paints its own outline over a designed ring, and `ui/style` has no `Outline` to turn one off with. The sheet names the classes an `On(.Focus, ...)` produced for a `Shadow`, `Shadows`, `BorderWidth` or `BorderEdge`. **`:where(:focus-visible){outline:none}` lost**: it leaves a control that styles nothing with no visible focus at all, which is the failure `State.Focus` being `:focus-visible` exists to avoid. A breakpoint-scoped ring keeps the platform's for the same reason — there is a width at which it paints nothing. |
| **A colour scheme is a `Theme` that binds no token** | `sources/ui_theme.buri`'s `scheme` | `color-scheme` is one declaration in the `:root` block a theme already writes, and `switching` flips it with the values it goes with. **A second parameter on `themed` lost**: a package writes `themed` and has no idea which scheme the app is in, and every existing caller would have had to say. **A field on `Theme` lost** for the same reason — the decision belongs where dark mode already lives, which is the app's list at `mount`. |
| **A button takes `[Node<C>]`, and a button with none shows its label** | `sources/ui_node.buri`'s `button`, `runtime.js` tag 5, `$tree_labelled` | `link`'s shape, applied to the one widget that had no children: a mark and a word are now one focusable element, so the wash that says hovered or says current page covers both. The label stays a parameter and rides in `aria-label`, so the accessible name is never the rendered glyphs — which is also what `press` addresses a button by, because a button's glyphs may be an icon. **Rendering the label only as an attribute lost**: it makes `button(label, styles, [], onPress)` an empty box, so every call site in the corpus would have had to repeat its own label as `[ui.text(...)]` to keep the picture it had. The fallback is one conditional in each of the three renderers and it buys the rule that a button is never blank. |
| **A labelled control has two style lists: `styles` on the input, `around` on the `<label>`** | `sources/ui_node.buri`'s `field` and `toggle`, `styles.rs`'s `Reset` | The `<label>` is the box a surrounding `row` measures, and nothing on the input can reach it — so `Grow(1)` landed on a child of a non-flex parent and `Width(.Full)` resolved against a shrink-to-fit label. **Splitting one list by property lost**: "the layout half goes outside" is a rule with no name in the vocabulary and no way for a reader to tell which half a property is in. **Moving the whole list to the wrapper lost too, and would have reverted #44**: `:focus-visible`, `:disabled` and `:checked` are the input's pseudo-classes, so `On(.Focus, ...)` on a label fires on nothing. The reset lays the wrapper out as a wrapping row rather than leaving it a browser's inline box, because a flex item is blockified and an inline `<label>` given `Grow` would have stacked its span and its input; `describe` writes that same arrangement as `[.Layout(.Row), .Wrap(true), .AlignCross(.Center), .Group(around)]`, so `around` beats it by the last-wins rule `row` already uses and the two renderers agree property by property. |
| **A toggle's mark is `ToggleKind` and the widget's own drawing, not a child and not a `Style`** | `sources/ui_node.buri`'s `ToggleKind` and `markLines`, `paint.rs`'s `Mark`, `styles.rs`'s `TICK_MASK` | An `<input>` holds no children, so "let `toggle` take `[Node<C>]`" cannot be implemented in a browser at all — the mark has to be the sheet's `::before` however it is spelled in Buri. A `Style.Mark(...)` lost for the opposite reason: a mark is a *shape*, there is no radius that makes a tick, and a property that can be left off is a control a program can leave with nothing to read its state by. So the kind is closed and required, and the scene carries `mark:thumb` and `mark:tick` beside `field:` and `image:` — a scene-only declaration saying what to draw in the element's own foreground. The two renderers draw one tick because they draw the same geometry: a stroke through `(3.5, 8.5)`, `(6.5, 11.5)` and `(12.5, 4.5)` of a sixteen-unit square, as a mask in the sheet and as a path in the painter. The reset now reaches `input[type=checkbox]`, which #44 deliberately left alone; `appearance:none` erases a browser's tick and there is something to draw a new one with, and the box it gives back is one rem square and unshrinkable, because an unsized `appearance:none` checkbox is invisible. |
| **A radio group is the widget `radioGroup`, not a `Role.RadioGroup` and not a `FieldKind.Radio`** | `sources/ui_node.buri`'s `radioGroup` and `radioOptions`, `runtime.js` tag 17, `styles.rs`'s `Reset` and `DOT`, `paint.rs`'s `Mark::Dot` | A radio group is the browser's own model — one tab stop for the group, ArrowUp/Down/Left/Right that move *and* select, Space, `aria-checked` and the roving `tabindex` — free the moment the options are `<input type="radio">` inside a `role="radiogroup"`, and unreachable otherwise: a stack of `button`s gives a reader a tab stop per option and announces "button". **`Role.RadioGroup` on its own lost**: the options still could not be radios, so the group would announce its count and hand back none of the key model. **`FieldKind.Radio` lost**: `field` binds a `Signal<Str>` to one input, and a radio's value is the group's, not the input's — the signal has to hold the *selected key*, over the whole choice. So the fix is a widget over the choice, the shape `each` and `form` already take: `radioGroup(label, options, styles, value)` with `options` a list of `(key, caption)`. The signal holds the selected key, the input whose key matches it is checked, and picking another writes its key back — the two-way binding a `field` has, since a radio fires `change` only on its way to checked. One `name` per group hands the browser the model; a counter makes it unique and a fresh render or worker request numbers from zero, so a resume into a fresh page names them the same. The dot follows the toggle's mark exactly: the widget's own drawing, `mark:dot` in the scene beside `mark:tick`, the reset's `input[type=radio]:checked::before` on a page, and a filled disc half the box across in the painter — `Foreground` the one colour that paints it. |
| **A second entry's artifact is named after its entry** | `build/actions.rs` `artifact_path` | Two outputs of one binary otherwise write one path. `main` keeps the directory's name, so nothing written before entries were nameable moves; `artifact_name` still overrides. |
| **`buri run` serves a page rather than a new `buri serve` doing it** | `commands/run.rs`, `commands/serve.rs`, `cli/run.md` | A second command is a second page, a second row in the command table, and a second set of refusals, all to say "build one binary and do the one thing that binary can be done with". `run` already chose the page for a binary that declares one, and already refused a worker; what changed is that starting a page means answering it over HTTP rather than handing the module to `bun`, which exited 0 having painted into a document nobody could see. The cost is written down: the `run` row in `repositories/build-files/several_entries` was a command that finished, and a server is not, so that claim moved up to `build::serving`, where the answer comes back over a socket. `--watch` there is `buri test --watch`'s loop with the page's build as its pass — the address is printed from the loop's arming callback, so an edit made after reading it is one the next pass sees. |
| **The shell answers every path that does not name a file** | `commands/serve.rs` `Page::answer` | A page routes on the address bar, so a static server answering `/main.html` hands the router `/main.html` and renders the not-found route, and a plain one 404s every deep link. The rule is the last segment's extension rather than "whatever is not on disk": answering the shell for a missing `/theme.css` tells a browser its stylesheet is HTML, and the mistake then reads as a page with no styles instead of a 404 anybody can act on. |
| **The entry name is in every cache key an output reaches** | `build/cache.rs`, `build/actions.rs` | Without it two outputs of one binary share a key, and the artifact for one entry is served for the other's. The entry is the root dead-code elimination walks from and the body the platform check is asked on behalf of, so the same sources produce different bytes. |
| **`shell` answers the document, and `http.html` answers the response** | `sources/web.buri`, `sources/http.buri` | The proposal's own line is `http.html(ctx, web.shell(...))`, so `shell` producing a `Response` would make that line ill-typed and give `ui/web` a second opinion about status codes and headers. A document is a string; turning one into an HTTP message is `core/net/http`'s job, and `html` is one line beside `json`. |
| **`render` takes the tree and no context** | `sources/web.buri` | The proposal writes `web.render(node)`. It is sound rather than merely short: every constructor in `ui/node` is unbounded in `C`, so nothing inside a tree can act on a context, and a handler is not called at all when what comes back is text. The runtime passes `null` where `mount` passes the caller's context. |
| **`resume` takes the tree, and adopts the markup rather than rendering it** | `sources/web.buri`, `backend/js/runtime.js` | The proposal writes `web.resume(ctx)` with no tree, and that shape shipped first: it read the embedded state and left the document alone. It cannot make a page work — a handler lives in a `Node`, so a resume with no tree has nothing to attach and a server-rendered button does nothing, which is the whole reason a page is shipped at all. So `resume(ctx, root)` runs the one renderer against the document that arrived: `$tree_element` and `$tree_text` answer with the node already sitting there, markers are inserted where the walk reaches, and what the pass adds is the listeners and the computations. Rejected: a second renderer that walks markup, which is a second thing to be right; and mounting over the top, which throws away exactly what the server sent. `web.state(ctx)` reads the embedded state before the resume rather than after it, because the tree is built out of it. A tree the markup does not match is `.Err` naming what was wanted and what was there — guessing would leave the reader looking at both answers. |
| **The proposal's `state.toJson()` is `state.toJson(ctx)`, and a page's text is prepared outside the closure** | `sources/json.buri`, `sources/ui_prop.buri`, `guides/websites.md` | Both are forced by signatures that predate the feature and neither is `ui/web`'s to change. `ToJson::toJson<C: Allocator>(self, ctx: C)` names an allocator because rendering allocates, and a worker has one. A `Computed` prop holds a `fn(Scope) => T`: a `Scope` reads the graph and grants nothing else, and a closure may not capture a capability (SPEC 10.6), so a route's closure cannot turn an interpolation into a `Str`. What varies is prepared where there is a context and captured, which is what the worked page does and what the guide says in the sentence beside it. |
| **The state crosses as JSON text in an inert `<script>`** | `sources/web.buri` | A `<script type="application/json">` is neither run nor rendered, and the page reads it by id. Every `<` in it is escaped as a JSON `<`, which is why a state holding `</script>` closes nothing. The alternative — a global assignment in a real script — is executable text built from user data. |
| **`Location` answers a signal, not a string** | `sources/effect.buri`'s `Location` | Every identifier in `platform/effect`'s reactive graph section is an `Int`, because that section is the boundary with a runtime holding one graph of untyped signals. A `Str` would make navigation invisible: `web.route` wraps the signal in a `Prop`, so a computation that read the path re-runs when the reader navigates, and `web.path` reads the same signal once. |
| **The graph a server-side render registers is dropped with the answer** | `backend/js/runtime.js` `$ui_web_render` | A worker's module state outlives the request, and a `computed` node registers a cell whether or not anything will ever read it again. The render truncates the graph back to the length it had, which is right because the tree is thrown away with the HTML. |
| **`ui/web` is JavaScript's alone** | `backend/runtime_table.rs`, `tests/native/conformance.rs` | Both platforms a website is built for are JavaScript, and a native artifact has no document under it. So there are no native runtime entries, a native build reaching one stops at code generation naming the operation, and the conformance package says `backends: [JS]` with that reason. That is about the *intrinsics* — `render`, `shell`, `resume`, `state`: `route`, `navigate` and `replace` are ordinary Buri over the graph, and `web/routing.buri` runs natively. |
| **Only HTML's own empty elements self-close in rendered markup** | `backend/js/runtime.js` `$dom_markup`, `sources/web.buri` | `<div />` is an *opening* tag to an HTML parser: everything after it lands inside. So an empty region swallowed the rest of the page, and a resume onto that markup saw a tree it did not match — a whole website broken by one `column([], [])`. `img`, `input` and `hr` keep the slash, because a closing tag for one of those is markup a browser refuses to nest. `ui/testing`'s `markup()` moved with it, since there is one serializer and the conformance package asserts the two renderers agree. A `textarea` came with it: what is typed into one is its text, not a `value` attribute. |
| **A resume refuses a shape and writes a value** | `runtime.js` `$adopt_claim`, `sources/web.buri`, `guides/websites.md` | An element that is missing, renamed, or unaccounted for is `.Err` naming what was wanted and what was there. A run of text or an attribute that differs is written in place, because the numbers a page renders come from a state that is allowed to have moved on. The rule was written down for text and not for attributes; it is the same rule and now says so. A **second** `resume` on one document is refused like any other disagreement — the first pass left markers the server never wrote — and the module says to resume once. |
| **`shell` writes the path it rendered for, and `resume` checks the address before the shape** | `sources/web.buri`, `runtime.js` `$ui_web_resume`, `guides/websites.md` | Two routes that render the same *shape* — a heading and a paragraph, say — adopt each other's markup and the walk finds nothing wrong, so a page resumed at the wrong address ends up showing one route's markup with the other route's handlers on it, silently. `shell` gained a `path` parameter and writes it as `data-path` on the state script it already emits; `resume` compares it against `location.pathname` first and answers `.Err` naming both. Rejected: comparing what the tree renders, which is the thing that cannot tell these apart. A query string and a fragment are not compared, because neither is part of a path — `Request.path` and `location.pathname` both leave them out, so one page does not become two when a reader arrives from a campaign link. Markup no `shell` wrote has no `data-path` and keeps the shape check alone. `resume` stays `C: Ui` rather than gaining `Location`: the address is read to check a precondition and never handed to the program, and `Ui` is `web` alone, so a resume is already only reachable where there is an address bar — requiring the grant would tax every page that does not route. |
| **A document's metadata is a struct on `shell`, and the page's own head is a `web` block on the binary rule** — **amended (#142): the block is gone, and a mounted page names its own tab from code** | `sources/web.buri`'s `Document` and `shell`, `schema/build.proto` `Binary`, `crates/stdlib/src/platforms/web/index.html` | Every Buri site was called **main** in the tab, because the generated `main.html` hardcoded the artifact's name, and a server-rendered one was called nothing at all — `shell` wrote no `<title>`, no `lang` and no viewport. So `shell` takes a `Document` — `title` and `lang`, built from `defaultDocument` — and the build rule takes the same two fields for the client-rendered shell, defaulting to the artifact's name so no repository's output moved. **A struct rather than more positional parameters**, because a head grows: a fourth string on `shell` would rewrite every call site again the next time one is added, and five strings in a row is five chances to swap two. **An effect — `web.setTitle(ctx, title)` — lost**: it would put the title in the tree's dependency graph to solve a problem the tree does not have, since a worker renders one document per request and knows the route before it builds anything. What an effect buys is the title following a client-side navigation, and there is no client-side navigation to follow (#49). Routing is a match, so a per-route title is a match too, and it is written where the route is decided rather than performed from inside the tree. The row below is the amendment: there *is* client-side navigation now, so the effect the paragraph above rejected is the only shape that works, and the build block it chose is deleted. |
| **A page's title is code, not a build rule: `web.title(ctx, Prop<Str>)` on the page, `Document` on the worker** | `sources/web.buri`'s `title`, `runtime.js`'s `$ui_web_setTitle`, `build/actions.rs` `copy_assets`, `crates/stdlib/src/platforms/web/index.html`, `schema/build.proto` `Binary` | The `web { title lang }` block was one constant in `main.html`, so every route of a client-rendered site shared one tab name — forty addresses, forty identical history entries, and a screen reader announcing all of them the same (#142). The block is removed outright rather than kept as a default: a build file is where a target is declared, and what a document is *called* is a function of the route, which only the program knows. What is left in `web`'s `index.html` is an empty `<title>` and `lang="en"`, a placeholder the page writes over as soon as it mounts. **A `Prop<Str>` through a watch, rather than a `Str`**, because the whole complaint is a title that cannot follow a navigation: a `.Const` names the tab once and a computation over `route` renames it every time, which is the same shape the tree already routes with. **`mount(ctx, root, themes, document)` lost**: `mount` is `ui/node`'s and would have to know `ui/web`'s `Document`, every mount in the corpus would be rewritten, and the title would freeze at mount anyway — the defect being fixed. **A `Document` on both halves lost** too: `shell` is ordinary Buri with an `Allocator` and no scope to read a prop under, so making the field vary would push a reactive read into the one path that has no graph. So the worker keeps `Document { title: Str, lang: Str }` read once, and the page gets one function beside it. |
| **A page navigates through two functions beside `route`, not through a writable `Signal<Str>`** | `sources/effect.buri` `Location`, `sources/web.buri` `navigate`/`replace`, `crates/stdlib/src/platforms/web/main.mjs` `HostLocation`, `sources/host_testing.buri` `Address`, `guides/websites.md` | `Location` was read-only, so nothing in a program could write the address and every navigation had to be a `ui.link` — a full document load, which rebuilds the tree and loses every signal the app was holding (buri-lang/buri#49). `navigate(ctx, path)` and `replace(ctx, path)` are `C: Location + Ui`: the effect gains `push` and `replace`, which move the address bar, and each function writes the signal `route` wraps itself, so the graph and the bar move together however the address was reached — a press here, or `popstate` when the reader goes back. Rejected: `Location` answering a `Signal<Str>` instead of an `Int`. It is the bigger change and the weaker one — `Signal`'s field is private to `ui/signal`, which a platform module may not import, so the handle would have to be mintable from `platform/effect` too; and a signal a program can `set` still cannot push a history entry, so the effect would have gained a writer anyway and the address bar and the graph could then be moved apart. The history entry is the *only* thing the two functions do differently, and only a browser has one, so the headless double implements `push` and `replace` as ordinary Buri that does nothing and the difference is asserted where a browser is — `language::a_website_is_rendered_by_its_worker_and_resumed_by_its_page`, over a history stack the document double keeps. That double is `platform/effect/testing`'s `Address`, one signal of the same graph and no runtime entry at all, which is why `web/routing.buri` is in the native conformance set beside `ui/reactivity.buri` while `web/document.buri` stays out. A worker needs nothing: only `WebHost` has a `location` field, so a worker that reaches for the address bar is already refused by `unknown-field` on the line that asked. |
| **A cell carries a fourth glue word, its type's own `Equal`, and the cutoff is `==` on every backend** | `runtime_table.rs`'s `Extra::Owned`, `Arg::Equal`, `stencil/glue.rs`'s `Helper::Equal`, `middle/derives.rs`, `cli/runtime/ui.rs`, `backend/js/runtime.js` `$ui_write` | A signal's rule is that writing a value equal to the one it holds re-runs nothing, and `==` is structural — so two strings with the same text are one value wherever they live. Both backends read it as *identity*: natively the graph compared the cell's raw bytes, which for a `Str`, a list or a record are a pointer, and `runtime.js` compared with `===`. So a `navigate` to the address already showing re-rendered natively, and a cell holding a list re-ran its watchers on the web whenever the list was rebuilt (buri-lang/buri#73). The graph cannot answer the question itself — a cell is bytes and the type does not cross — so `signal` and `write` carry the comparison beside the retain and the release they already carried: `middle::derives`'s generated `Equal` behind a `void(frame, a, b, out)` thunk each backend emits, null for a type nothing was generated for and then the bytes are the fallback. `frame` is the word `Extra::Compute` spells `frame_at`: the comparison is Buri code, the frame-threaded backend needs a frame to run it in, and the LLVM one ignores it. Rejected: a structural walk generated from the *layout*, like the retain and release walks beside it — it is a second implementation of derived equality in each of two backends, against one that `middle::derives` already generates once and `native::agreement` already holds to JavaScript's answer. Also rejected: bounding `Signal::set` on `T: Equal`, which changes what a signal is to fix what a write does. The cost is that a write of a big list now compares it, which the guide's cost table says. |
| **A worker's tree holds no `field` and no `toggle`** | `sources/ui_node.buri`, `guides/websites.md` | Both bind to a `Signal`, and `signal` names `Ui`, which is `web` alone. So a form cannot be server-rendered today. Recorded rather than fixed: making a `Signal` without `Ui` is a change to what a cell *is*, not to `ui/web`, and the guide says what to do instead. |
| **A control's styles are a parameter on `button`, `link`, `field` and `toggle` — not a `styled(styles, node)` wrapper — and the sheet opens with a reset for the elements the program builds** | `sources/ui_node.buri`, `backend/js/runtime.js` `$tree_render`, `semantics/styles.rs` `Reset` | The wrapper's one argument is that it keeps every call site compiling. It cannot pay for itself anywhere else: there is one renderer and it builds an element from the node it is standing on, so a wrapper would have to reach into the node it holds and hand the styles down — the parameter, with a variant in front of it, in `$tree_render`, in `web.render`'s markup and in `describe`'s scene document alike. Every call site in the repository moved instead. A field's and a toggle's styles land on the input rather than the label around it, because the input is what a browser focuses and disables.
