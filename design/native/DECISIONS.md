# The decision index

Everything in `design/native/` is decided. This file is the index: one row per
decision that was close enough to be worth arguing, the document where it is
argued in full, and the alternative that lost.

It exists because the arguments are spread across six documents and a reader
who wants to know *whether* something was considered should not have to read all
seven to find out. Where a row and its document disagree, the document is right —
this is a table of contents, not a second source.

Nothing here is open. Work that is not done is in
[`design/TODO.md`](../TODO.md), under "The native backend"; a decision that is
reversed is reversed in the document that made it, with the reversal recorded
there rather than deleted.

| Decision | Where | The alternative that lost |
|---|---|---|
| Reference counting, not a GC | MEMORY.md §3 | A tracing GC needs statepoints or conservative scanning; the first contradicts CODEGEN-LLVM.md §0's second instruction, the second makes the heap data-dependent and irreproducible. |
| `Checked` is bounded by the numbers the *backend* has | VALUE-MODEL.md §11, SPEC §6.2.2 | A native backend that also stopped at 2^53 shipped for a wave and was reversed: it makes `Checked` useless on `I64` natively, and buys portability of a result nobody should branch on. |
| `Str` slicing keeps its parent buffer alive, and that is not a language question | MEMORY.md §5.3, §6 | Copying above a ratio makes `slice` name `Alloc` and retracts `core/str`'s purity claim; copying on proven retention is a real analysis for a case that is hard to detect, and stays available precisely because it is not language-visible. |
| Exactly one supported LLVM at a time, tracking the latest both inkwell and the flake carry | CODEGEN-LLVM.md §8.1–8.3 | "The flake leads" forbids a bump the backend needs; "the backend leads" prices a nixpkgs bump — which moves `cargo`, `bun`, `elan` and therefore `buri`'s own hash — into a routine chore. Multi-version support is refused permanently: two LLVMs means one attribute encoded two ways. |
| No arena per `Alloc` scope | MEMORY.md §4 | `Alloc` is a propagating bound and `Region` is a value; there is no scope to hang an arena on. |
| The middle end owns tail-call elimination; no backend uses its own | CODEGEN-LLVM.md §5 | `musttail`/`tailcc` and `return_call` are both viral, both incompatible with a C-ABI runtime, and both unnecessary once the tail-call graph is a DAG. The `return_call` half was argued in CODEGEN-CRANELIFT.md §3.3 and went with that document on 2026-08-29 (CODEGEN-STENCIL.md §13); the row is unchanged, because the reason never rested on it. |
| Neither linker links incrementally; recompile granularity is the codegen unit | CODEGEN-STENCIL.md §12 | mold rejected incremental linking partly *because it is not reproducible*, which this toolchain cannot accept. |
| A `stat` sweep over the declared source set, not `notify` | BUILD-AND-WATCH.md §1.2 | A general watcher is hard (Zed abandoned its own; Zig abandoned kqueue) and unnecessary when the input set is enumerated by the cache keys already. |
| One codegen unit per source module, in both profiles; no LTO | ARCHITECTURE.md §5 | Per-function objects lose colocated direct calls; a merged fixed count loses reuse; LTO re-derives an inlining decision the middle end took with an exact call graph. |
| `Str` is 24 bytes with a `base` pointer; `[T]` is 16 | VALUE-MODEL.md §3-4 | A uniform 16-byte shape would make `slice` allocate, contradicting `core/str`'s own contract. |
| Descriptors are folded at compile time and never reach a native artifact | VALUE-MODEL.md §9 | A runtime walker is an interpreter, defeats every memory attribute, and defeats DCE. |
| A context of zero-sized implementations costs nothing | VALUE-MODEL.md §8 | Nothing lost; `ctx_layouts` already records the layout statically. |
| `nsw`/`nuw` are never emitted | CODEGEN-LLVM.md §3.4 | Correct per SPEC 6.2, and it would replace a debuggable wrap with whatever the optimizer inferred. |
| `willreturn` only where the backend proved there is no cycle | CODEGEN-LLVM.md §3.6 | Reading the design's *"a function `middle` proved terminates"* as `Purity::Pure` with no abort — which miscompiled every pure non-tail recursion at `default<O2>`: `memory(none)` + `willreturn` is `speculatable`, and LLVM hoisted the recursive call above its own base case. Also rejected: keeping the attribute for a loop, which is `mustprogress` by another name and licenses deleting a divergence SPEC 10.4 calls observable. The row a decreasing-measure analysis in `middle` would take back is named in §3.6 rather than claimed. |
| Cranelift pinned to the wasmtime 36 LTS — **reversed 2026-08-29**, with its subject | CODEGEN-STENCIL.md §13 | Tracking latest meant a monthly `identity()` change, which invalidated every cached object in every repository. The pin was answering a question the removal deleted: there is no version left to bump. |
| `backend-llvm` off by default; `backend-stencil` on | BUILD-AND-WATCH.md §2 | `cargo install buri` must not need a system LLVM. `backend-cranelift` was on by default beside `backend-stencil` until **2026-08-29** (CODEGEN-STENCIL.md §13); what is left needs nothing a machine able to link a native artifact does not already have, and adds nothing to the lockfile. |
| The stencil backend is the debug backend — **reversed 2026-08-29** | ARCHITECTURE.md §4, CODEGEN-STENCIL.md §13 | It was compiled in and never selected for as long as the seat was a decision about parity rather than about plumbing. Parity was met — 997 of 997, the same six refusals, the same blocks live at exit — so the decision was taken and Cranelift was removed: 38 transitive crates to 0, a clean release build in half the time, and x86-64 covered by writing the emitter rather than by keeping a second code generator. What lost, and is written down rather than repaired: a 1.38× debug runtime, and a `buri` 5.06 MB *larger* rather than smaller — the machine code halved but the stencil libraries the old binary dead-stripped are the code generator now (PERFORMANCE.md §5). The one behavioural difference the flip would have carried — `str.concat` allocating unconditionally — was closed before the flip rather than accepted with it (CODEGEN-STENCIL.md §5.0.1). |
| Cross-*linking* refused, explicitly; cross codegen supported | ARCHITECTURE.md §9 | The blocker is the host-only runtime archive rather than any backend, and naming that makes the fix a packaging problem rather than a compiler one. |
| `Arena` is accounting-only in v1 | MEMORY.md §7.2 | A real region-freeing arena needs a scoped-context construct the language does not have. |
| One symbol prefix, `buri_rt_`, for every runtime entry including the host ones | VALUE-MODEL.md §10 | A split `buri_rt_` / `buri_host_` makes "is this symbol the runtime's" a table lookup in the one place a compiler asks it per call site. |
| The v1 allocator is `malloc`-backed with no size classes | MEMORY.md §5.4 | Nothing observable differs — the header, the capacity, the reuse test and the *defined* `Alloc` cost model are identical — so the free lists can land later under a green suite instead of being co-developed with two backends. |
| The runtime archive is precompiled by `cli/build.rs`, not compiled on demand | BUILD-AND-WATCH.md §2.2 | On demand puts a `rustc` in the build loop and makes the archive hash depend on whatever `rustc` was on `PATH` at *use* time. |
| `Net::fetch` is cleartext `http://` only, and says so — **reversed 2026-08-30**, with its subject | `cli/runtime/http.rs`, `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | `https://` works. It goes through `rustls` over the `ring` provider, the server's certificate is checked against the host's trust anchors, and a certificate that does not check out is a `NetError::Transport` naming what was wrong and which trust set it was checked against. The half of the original row that never depended on the refusal still stands and is now structural: a client that silently downgraded to cleartext would be worse than one that refuses, and `http.rs` cannot downgrade, because the scheme decides one thing — whether the socket is wrapped — and nothing else. What the reversal costs is 1.72 MiB in every binary this compiler produces (§1.1.2), which is over the size budget CI carried and is re-stated there rather than absorbed. A `net`-off toolchain keeps the refusal, and its message names the feature. |
| One bar, **two** admitted sets: the toolchain's and the runtime's — **amended 2026-08-30** | root `Cargo.toml`, BUILD-AND-WATCH.md §1.1, §1.1.1 | One list would have made "tokio is in the compiler" and "tokio is in every program the compiler produces" the same sentence, and they are not the same decision: `libburi_rt.a` is linked into every native binary, so the runtime's set is a set strangers ship. The amendment is a split, not a weakening — the same three clauses, plus a fourth on the runtime's side that the toolchain's does not carry: the set is closed by an **exact list**, asserted as an equality, so a fifth crate and a removal both fail a test. The alternative that lost was one bar and one list with the runtime's entries marked, which loses the fourth clause and the asymmetry that motivates it. |
| The runtime's four networking crates land **referenced by nothing** — **amended 2026-08-30** twice, and three of the five now are | `cli/runtime/net.rs`, `manifest.toml`, `rt.rs`, `tls.rs` | Landing them with their first caller would have made the archive's growth and the code that needed it one commit, and the growth is the part that is irreversible: the archive is `include_bytes!`d into every `buri` binary. Measured first instead — 5 987 472 → 5 987 496 bytes, twenty-four, because fat LTO drops what nothing reaches — and held there by a CI symbol-table check that each later slice had to move deliberately. Both did. B6 linked the reactor: `rt.rs`, 6 035 480 → 6 220 904 bytes, +185 424 on aarch64-apple-darwin. C7 linked the TLS client, and added `ring` as the fifth crate already reached: `rustls` and `ring` left the "must be absent" list and joined a "must be present" one in the commit that reached them, +1 804 592. `hyper` and `tungstenite` are still referenced by nothing and the check still says so. The convention worked exactly as designed both times — each figure was a number in a report before it was a number in a binary, and the 1.72 MiB is what moved the size budget rather than what was discovered under it.
| The archive's feature list is a **file beside the archive**, and the refusal for a missing one is a **diagnostic before codegen** | `cli/build.rs`, `backend/runtime_native.rs`, `backend/mod.rs`, `docs/errors/networking-not-available.md` | Three ways the toolchain could learn whether its runtime has `net` were open: a `cargo:rustc-env`, a byte written beside the archive, or reading `buri_rt_net_capabilities` back out of the archive's symbol table. The file wins for the reason the baked digest is a file — one `OUT_DIR` written by one run of the build script, so a stale directory cannot pair one build's bytes with another's answer — and it generalises to `net-h3` as a second line rather than a second mechanism. Reading the symbol table would make the toolchain parse `ar` and Mach-O/ELF to learn something the script already knew. What it is *for* is the second half: `Backend::missing_intrinsics` reports the `host.HostListen.*`/`HostSockets.*`/`HostTasks.*` family as missing when the archive has no `net`, so the failure is a sentence naming the operations and the feature, before code generation, rather than an unresolved `buri_rt_*` symbol from `cc`. The refusal landed **before the keys exist**, on purpose: the alternative is that the first toolchain built without networking meets them as a link error. |
| Native suspension is a **carrier thread plus a run baton**, not a CPS transform | `cli/runtime/rt.rs`, design/native track B §0.1 | Buri machine code stays ordinary frame-threaded synchronous code and a suspending host call is one `park_on`. The baton — exactly one carrier in Buri code at a time — is what lets *concurrency* land while *parallelism* does not, so non-atomic refcounts, the single-threaded allocator and every `rc == 1` in-place update stay correct untouched and atomic RC lands as its own priced slice (track G) rather than as everyone's prerequisite. The alternative, a native CPS/state-machine transform, is larger than the two shapes `middle/mod.rs` and CODEGEN-LLVM.md have each already rejected, put together. Phase 2 (B9) replaces the thread with a stack switch behind the same `park_on`. |
| The step ABI carries an **index word on every step**, not only on the keys that read one | `cli/runtime/list.rs`'s `StepEntry`, `backend/intrinsic_keys.rs` | `effect Tasks` promises the step its item's own index, and only the side driving the walk has one: deriving it inside the entry thunk means dividing `arg - base` by the stride, which needs a base the state record does not carry and which stops being true the moment a scheduler hands elements out of order — which is what D4 makes `parallel` do. Putting the word on `Tasks.parallel` alone was the alternative, and it costs *two* C signatures at a boundary whose whole value is that there is one: the runtime would have to know which shape a key is before it could call the thunk. `list.mapCtxStep`'s closure has no index parameter, so its thunk leaves the register unread — one register against a second ABI. |
| `Tasks` is granted on `LINUX`, `MACOS` and `JS`, and **withheld from `WEB`** | `standard_library/mod.rs`, `cli/tests/reject/tasks_not_granted_on_web` | Not a limitation of the backend: `WEB` and `JS` share a code generator, so `Promise.all` would run there. It is the judgement `Net`'s row made until `fetch` stopped waiting — `parallel` returns only when its last task has finished, and a page has an interface that a wait is visible in. Every effect a page's host does grant either answers instantly (`Ui`, `Watch`) or suspends without holding the event loop, which is what let `Net` onto `WEB`; granting a *waiting* effect there puts back the one shape that host is built to avoid, in the one place a program cannot leave. The callback-shaped task surface a page would want is the servers' slice, not this one. |
| `Tasks.parallel`'s body is in **`rt.rs`, behind `net`**, rather than beside the other list walks | `cli/runtime/rt.rs`, `backend/runtime_native.rs` | The body needs no reactor today, so a featureless home would have compiled. It would also have made `net_intrinsic`'s refusal — which names the `host.HostTasks.*` family and was written a wave before any of those keys existed — a lie for exactly as long as it took D4 to make it true again. Putting it here means the refusal was *exercised* by the first key that reached it (a `BURI_RUNTIME_NET=0` toolchain refuses a `core/tasks` program by name, before code generation) rather than re-argued later. **Amended 2026-08-30**: the body is a fan-out onto the carrier pool rather than a loop, which is what D4 made true; the placement argument is unchanged and is now load-bearing rather than anticipatory — the scheduler needs the reactor the feature admits. |
| Whether a fan-out is legal is the **artifact's statement about itself**, made once at startup, not a word on the step boundary | `cli/runtime/lib.rs` §6, `backend/llvm/runtime.rs`'s `FRAMES_PER_CARRIER` | `Tasks.parallel` may only run two steps at once where two steps may have live frames at once, and that is a fact about where a Buri frame lives. Under LLVM a frame is a machine frame, so a carrier's own thread stack is its own; under the frame-threaded backend a program has one `buri$stencil$stack` and an entry thunk works in a frame the *call site* set aside, so two steps of one `parallel` would share it and a step that suspends would still be holding it. `buri_rt_frames_are_per_carrier()` is therefore one optional call in the emitted `main`: silence is the safe answer and the old behaviour — steps in index order on the calling carrier — so an entry point that forgets it is slow and never wrong. The alternative was a **lane count on `Extra::Step`**: a fifth word saying how many steps this call site can hold frames for. It is the wrong altitude — the answer is the same at every call site in an artifact — and it widens a boundary two backends and two runtime entries have to agree on, `list.mapCtxStep` included, to carry a constant. B7 is what deletes this row rather than changes it: once each carrier acquires a Buri stack, both backends make the statement and the branch has one arm. |
| The fan-out is a **sliding window of 64 carriers**, not one carrier per item | `cli/runtime/rt.rs`'s `IN_FLIGHT` | A carrier is an OS thread with a 512 KiB stack, so the width is address space: 64 is 32 MiB per level of nesting. Unbounded is the shape that matches `Promise.all` exactly and is the wrong shape while a task costs a thread — a list of ten thousand items asks the kernel for ten thousand threads, which macOS refuses long before memory runs out, and `spawn_carrier` turns that refusal into an abort on a program JavaScript runs. The window costs the (n+1)-th task the wait for the first, and costs the answer nothing: the `[B]` is filled by index either way, which is the whole worth of the order promise. B9 removes the bound rather than raising it — a parked task that costs a stack switch and no thread has no reason to be counted. |
| `HostGrant::elsewhere_clause`'s **empty case is kept with no row using it** | `standard_library/mod.rs` | `Tasks` was the one ungrantable effect and is now granted, so nothing in the table exercises the branch, and the `!platforms.is_empty()` assertion D1 removed stays removed; the test builds a row of its own instead. Deleting the branch because its first user graduated would mean rediscovering "build this for a platform that grants it:" with nothing after the colon on the day the next effect lands ahead of its runtime — `Listen` and `Sockets` are both coming that way. Six lines and one test, against a diagnostic that reads like a compiler bug. |
| The carrier pool and the task table get **no `buri_rt_task_*` C ABI yet** — **amended 2026-08-30**, the file has its first export | `cli/runtime/rt.rs` §2 | An exported symbol is a contract both backends emit calls into. Writing one before a backend has a call to emit is a guess about a signature, and a wrong guess is a miscompile that shows up as a wrong answer at run time (`lib.rs` §1's whole argument). The table was Rust-visible in B6 and gains its first exported entry in track D, where the caller exists. D3 is that slice, and the convention held: `buri_rt_host_tasks_parallel` landed with both runtime-table rows and a caller in the same commit, and its C signature is what those rows describe rather than a prediction of one. The archive grew by the 544 bytes it costs, 6 220 904 → 6 221 448 on aarch64-apple-darwin. The *pool and the table* still have no C ABI: nothing yet starts a task from Buri code, and `task_start`/`task_join` stay Rust-visible until a backend has a call to emit for them too. |
| `rustls` is admitted with **no crypto provider** — **reversed 2026-08-30**; the provider is `ring` | `cli/runtime/manifest.toml`, `cli/build.rs`, BUILD-AND-WATCH.md §1.1.2 | Deferred until the bytes were bought rather than spent, which is now. `ring` over `aws-lc-rs` because `aws-lc-rs` wants `cmake` at build time and `ring` wants a C compiler the toolchain already requires for the stencil library and for every link; over the pure-Rust providers because `rustls-rustcrypto` says of itself that it is unaudited and not for production, and this archive is in every binary a stranger ships. The "turns degrades-rather-than-breaks into breaks" objection was real and is answered rather than accepted: `cli/build.rs` **probes** for `cc` before the build and falls back to `--no-default-features` with a `cargo:warning`, so a host without one gets a working toolchain, working `http://`, and an `https://` that refuses at run time naming the feature. A probe rather than a retry-on-failure, because retrying a failed compile with the feature off would also hide a bug in the runtime's own TLS code as a silently net-less toolchain. |
| Trust anchors come from the **host's PEM bundle**, with `SSL_CERT_FILE` overriding — and from no crate | `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | The two crate answers both lose on the bar's first clause. `webpki-roots` is a quarter-megabyte of *data this repository would ship*, pinning the trust set to a crate version rather than to the machine, so a user who installed a corporate root would have told their machine something a Buri program could not hear. `rustls-native-certs` reads the right thing and costs three transitive crates plus a link-time `Security.framework` on macOS — which a `staticlib` handed to `cc` by `build/link.rs` cannot carry without every artifact's link line growing a flag. Reading `/etc/ssl/cert.pem` and its four Linux spellings is forty lines. What it does not do is read the macOS keychain, and that is what `SSL_CERT_FILE` is for — the spelling OpenSSL, `curl` and `git` already honour, so it is one a user has met. Not cached across calls: a `OnceLock` would save a millisecond against a handshake that costs tens and would make "which roots" depend on when in the process the first request happened. |
| The runtime crate's own unit tests are **run**, by a test in the toolchain's suite that shells out to `cargo test` | `cli/tests/native/runtime.rs`, `cli/build.rs` | `cli/runtime` is a package that is deliberately not a workspace member and whose manifest is deliberately not named `Cargo.toml`, so `cargo test -p buri` could not reach inside it and no CI step did either — fifty-odd assertions about the float formatter, the UTF-16 comparison, the handle table and the allocator had been written and never executed. The `https://` slice needed a home for a test that starts a `rustls` server, and the only `rustls` in this repository is inside that package: the toolchain's own crate cannot grow a dev-dependency on it without failing `dependencies_stay_behind_the_bar`. So the seam was built rather than the bar bent. The path comes from `cargo:rustc-env=BURI_RT_PKG`, written by the build script that assembled the package, and the nested `cargo` gets the same environment scrubbing the build script's does. |
| The runtime's cargo package is **assembled in `OUT_DIR`**; its manifest in the tree is `manifest.toml` | `cli/build.rs` §1, BUILD-AND-WATCH.md §2.2 | `cargo package` skips any subdirectory of a package that holds a `Cargo.toml` — unconditionally, ahead of `include`/`exclude`, in both its listers — so `cli/runtime/Cargo.toml` deleted the whole directory from the published crate and a registry `cargo install buri` failed in the build script with nothing to compile. `include = ["runtime/**"]` was tried and does not override it. Publishing `buri-rt` as its own crate is the other answer and remains available; it is a registry decision with a release process attached, and this one is a rename. What it costs is `cd cli/runtime && cargo build`, which no longer resolves — the build has one driver and it is `cli/build.rs`. |
| The archive is linked **only when the objects reference it**, and the question is asked of the objects rather than of the program | `build/link.rs`, `build/actions.rs::link_key_of` | The design proposed a reachability query of `missing_intrinsics`'s shape — a walk of `program.funcs` for intrinsic keys. It would have been wrong, and wrong in the direction that fails a link: a program's intrinsic keys are not the whole of what it asks the archive for. Both native entry points call `buri_rt_argv_init` and `buri_rt_flush` unconditionally, reference counting reaches `buri_rt_alloc`/`buri_rt_free`, a division emits `buri_rt_abort_div_zero`, `==` on `Str` emits `buri_rt_str_eq` — and none of those is a `FuncKind::Intrinsic` anything could walk for. Asking the emitted objects for the one symbol prefix `buri_rt_` needs no third copy of every emitter's structural calls and cannot go stale when one moves. **The measured consequence, stated rather than buried: the answer is `Linked` for every Buri program, hello world included, and no artifact got smaller.** Dead-stripping is still what decides the size (370 288 bytes for `main() { .Ok(()) }` against a 6 035 480-byte archive). What the decision does buy today is the `link` key: an artifact that names no archive no longer carries the archive's digest, so it stops being relinked when the runtime changes. The alternative that lost is leaving it a constant, which keeps that term unconditional and leaves the day an entry point stops needing the runtime as a change to the key format rather than a change to one answer. |
| The flake vendors **both** lockfiles into one directory, and asserts the archive it produced | `flake.nix`, BUILD-AND-WATCH.md §3.2 | Merging the *lockfiles* was the obvious reading of "one `importCargoLock` takes one `lockFile`" and it loses to nixpkgs' own hook: `cargoSetupPostPatchHook` diffs the vendor directory's `Cargo.lock` against `src`'s and aborts when they differ, so a merged lockfile has to be un-merged before the build starts. A vendored `directory` source is a flat set of `name-version` directories, so merging *those* is a symlink loop and leaves `Cargo.lock` the toolchain's byte for byte. Leaving the gap open was the third option and is what shipped for a day: `nix build` stayed green and produced a toolchain with no native backend, which is a different compiler under the same version number — hence `assert-runtime-archive.sh` in the derivation's `postBuild`, where the four systems `eachDefaultSystem` covers are all systems `cli/build.rs` supports and an empty archive can only be a bug. |
| The carrier entry ABI is **one signature in a third file**, fixed before its first caller | `backend/carrier.rs`, `backend/stencil/asm.rs`, `backend/llvm/emit.rs` | This is the opposite call from `rt.rs` §1's, and the asymmetry is the argument. That row refuses to export a *runtime* symbol before a backend has a call to emit, because only the runtime knows its shape. This symbol is the **backend's**, and two of them emit it under one name for one caller: if they disagree, whichever the scheduler calls first decides what the other meant, and nothing — not the compiler, not the linker — says so. So the shape is written down once, both emitters are built from it, and a unit test renders each side back out (`carrier::ENTRY.render()` against an LLVM `FunctionType`'s printed form) and diffs the bytes. What is *not* shared is what is behind the door: stencil takes a Buri data stack from the runtime, LLVM takes none. `state` is passed and unread until a call site exists to fill it — a parameter added later moves every call site there is by then. |
| A carrier's Buri stack is **`mmap`ped per carrier**; `main` keeps the `__bss` block | `cli/runtime/memory.rs`, `backend/stencil/asm.rs` | One 64 MiB `__bss` block with one `PROT_NONE` guard is right for one thread and wrong for two: a second carrier's frames would land in the first's, and the fault a runaway recursion is meant to take at the guard would be a silent overwrite of somebody else's locals. The alternative considered was making the *static* block per-thread — a TLS `__bss` array — which multiplies 65 MiB of address space by every thread a program ever starts, whether or not it enters Buri code, and which cannot be `mprotect`ed once because each copy has its own address. `main` is deliberately left alone: a program that never starts a carrier makes no system call it did not make before, faults nowhere new, and links no door (`-dead_strip` deletes it). The runtime declares `mmap`/`mprotect`/`munmap` itself rather than adding `libc`, because the dependency set is closed by an exact list — and the *compiler* already emits a `bl mprotect` into every artifact, so the symbol is not new. |
| `TestTasks.parallel` drives the **same closure trampoline** the real one drives, rather than being a Buri loop — **reason amended 2026-08-30** | `sources/host_testing.buri`, `backend/intrinsic_keys.rs`, `cli/runtime/testing.rs` | A Buri body was written first, and the reason recorded for rejecting it was that a method body has no name for the caller's context. That reason is gone: the context is a named parameter now (the row below), and `SerialTasks` in the conformance corpus is a Buri body that passes it. The decision stands on the reason that was always the stronger one — **the order is the runtime's**. What this double decides is which permutation runs, and a permutation of `0..n` with a fault plan and a call log is not something a Buri body can choose; going through `step_call` also puts the double on the boundary the program will ship on, with exactly one thing changed. What it costs is a third `Extra::Step` key and a `self` that is `Arg::Scalar` where `host.HostTasks.parallel`'s is `Arg::Dropped`, because a `TestTasks` is a handle and the runtime has to ask it which order this run schedules in. |
| `Self` is the **implementing type everywhere**, and a callback meant to receive the caller's context takes a named `ctx` parameter instead | `sources/effect.buri`, `docs/lang/effects.md` §10.6, `semantics/expressions.rs`'s `implementing_ty` | `Tasks.parallel` was declared `f: fn(Self, Int, A) => B` and documented as handing the step "the full context", and those are two different values: `Self` is what implements the effect, which through a `context { … }` grants that one effect and nothing else. The trampoline delivered what the signature said, so a step reading `c.nowMillis()` answered `0` natively and *threw* on JavaScript — two backends disagreeing, which is worse than either being wrong. Both readings were reachable and one rule had to win. **Redefining `Self`-inside-a-callback to mean the caller's context lost**, and the reason is SPEC 10.9: an effect is an ordinary interface and anyone may write a type satisfying it. A callback parameter typed "the caller's context" has a type no `impl` can name and no value an `impl` holds, so no implementation written in Buri could ever call its own callback — `parallel` would have been implementable only by the compiler's own trampoline, and every hand-written fake would have been a different mechanism from the one that ships. Naming it costs one parameter and one repeated argument at one call site (`ctx.parallel(ctx, …)`, inside `core/tasks`), and buys: the front end needs no special case, `rewrite_call_args`' `Self` correction stops applying to the one method that must not have it, the "opaque `Self` inside a generic body" hole `self-subst-fix.md` §7 names does not arise for this shape at all — `C`'s bounds are the caller's — and `SerialTasks` is a nine-line Buri implementation that honours the promise. The native cost is nothing: `ctx` is `Arg::Dropped` in both tables, so the C signature of `buri_rt_host_tasks_parallel` is unchanged, and the value reaches the step through the state record slot `StepCall.ctx` already described. `Listen.listen` keeps `fn(Self, Request)` deliberately — its handler is meant to inspect the acceptor — and will gain a `ctx` beside it when `core/net/server`'s hooks need one. |
