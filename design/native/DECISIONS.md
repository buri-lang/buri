# The decision index

Everything in `design/native/` is decided. This file is the index: one row per
decision that was close enough to be worth arguing, the document where it is
argued in full, and the alternative that lost.

It exists because the arguments are spread across six documents and a reader
who wants to know *whether* something was considered should not have to read all
seven to find out. Where a row and its document disagree, the document is right —
this is a table of contents, not a second source.

Nothing here is open. Work that is not done is in
[`design/TODO.md`](../TODO.md), under "The native backend"; a decision that is
reversed is reversed in the document that made it, with the reversal recorded
there rather than deleted.

| Decision | Where | The alternative that lost |
|---|---|---|
| Reference counting, not a GC | MEMORY.md §3 | A tracing GC needs statepoints or conservative scanning; the first contradicts CODEGEN-LLVM.md §0's second instruction, the second makes the heap data-dependent and irreproducible. |
| `Checked` is bounded by the numbers the *backend* has | VALUE-MODEL.md §11, SPEC §6.2.2 | A native backend that also stopped at 2^53 shipped for a wave and was reversed: it makes `Checked` useless on `I64` natively, and buys portability of a result nobody should branch on. |
| `Str` slicing keeps its parent buffer alive, and that is not a language question | MEMORY.md §5.3, §6 | Copying above a ratio makes `slice` name `Alloc` and retracts `core/str`'s purity claim; copying on proven retention is a real analysis for a case that is hard to detect, and stays available precisely because it is not language-visible. |
| Exactly one supported LLVM at a time, tracking the latest both inkwell and the flake carry | CODEGEN-LLVM.md §8.1–8.3 | "The flake leads" forbids a bump the backend needs; "the backend leads" prices a nixpkgs bump — which moves `cargo`, `bun`, `elan` and therefore `buri`'s own hash — into a routine chore. Multi-version support is refused permanently: two LLVMs means one attribute encoded two ways. |
| No arena per `Alloc` scope | MEMORY.md §4 | `Alloc` is a propagating bound and `Region` is a value; there is no scope to hang an arena on. |
| The middle end owns tail-call elimination; no backend uses its own | CODEGEN-LLVM.md §5 | `musttail`/`tailcc` and `return_call` are both viral, both incompatible with a C-ABI runtime, and both unnecessary once the tail-call graph is a DAG. The `return_call` half was argued in CODEGEN-CRANELIFT.md §3.3 and went with that document on 2026-08-29 (CODEGEN-STENCIL.md §13); the row is unchanged, because the reason never rested on it. |
| Neither linker links incrementally; recompile granularity is the codegen unit | CODEGEN-STENCIL.md §12 | mold rejected incremental linking partly *because it is not reproducible*, which this toolchain cannot accept. |
| A `stat` sweep over the declared source set, not `notify` | BUILD-AND-WATCH.md §1.2 | A general watcher is hard (Zed abandoned its own; Zig abandoned kqueue) and unnecessary when the input set is enumerated by the cache keys already. |
| One codegen unit per source module, in both profiles; no LTO | ARCHITECTURE.md §5 | Per-function objects lose colocated direct calls; a merged fixed count loses reuse; LTO re-derives an inlining decision the middle end took with an exact call graph. |
| `Str` is 24 bytes with a `base` pointer; `[T]` is 16 | VALUE-MODEL.md §3-4 | A uniform 16-byte shape would make `slice` allocate, contradicting `core/str`'s own contract. |
| Descriptors are folded at compile time and never reach a native artifact | VALUE-MODEL.md §9 | A runtime walker is an interpreter, defeats every memory attribute, and defeats DCE. |
| A context of zero-sized implementations costs nothing | VALUE-MODEL.md §8 | Nothing lost; `ctx_layouts` already records the layout statically. |
| `nsw`/`nuw` are never emitted | CODEGEN-LLVM.md §3.4 | Correct per SPEC 6.2, and it would replace a debuggable wrap with whatever the optimizer inferred. |
| Cranelift pinned to the wasmtime 36 LTS — **reversed 2026-08-29**, with its subject | CODEGEN-STENCIL.md §13 | Tracking latest meant a monthly `identity()` change, which invalidated every cached object in every repository. The pin was answering a question the removal deleted: there is no version left to bump. |
| `backend-llvm` off by default; `backend-stencil` on | BUILD-AND-WATCH.md §2 | `cargo install buri` must not need a system LLVM. `backend-cranelift` was on by default beside `backend-stencil` until **2026-08-29** (CODEGEN-STENCIL.md §13); what is left needs nothing a machine able to link a native artifact does not already have, and adds nothing to the lockfile. |
| The stencil backend is the debug backend — **reversed 2026-08-29** | ARCHITECTURE.md §4, CODEGEN-STENCIL.md §13 | It was compiled in and never selected for as long as the seat was a decision about parity rather than about plumbing. Parity was met — 997 of 997, the same six refusals, the same blocks live at exit — so the decision was taken and Cranelift was removed: 38 transitive crates to 0, a clean release build in half the time, and x86-64 covered by writing the emitter rather than by keeping a second code generator. What lost, and is written down rather than repaired: a 1.38× debug runtime, and a `buri` 5.06 MB *larger* rather than smaller — the machine code halved but the stencil libraries the old binary dead-stripped are the code generator now (PERFORMANCE.md §5). The one behavioural difference the flip would have carried — `str.concat` allocating unconditionally — was closed before the flip rather than accepted with it (CODEGEN-STENCIL.md §5.0.1). |
| Cross-*linking* refused, explicitly; cross codegen supported | ARCHITECTURE.md §9 | The blocker is the host-only runtime archive rather than any backend, and naming that makes the fix a packaging problem rather than a compiler one. |
| `Arena` is accounting-only in v1 | MEMORY.md §7.2 | A real region-freeing arena needs a scoped-context construct the language does not have. |
| One symbol prefix, `buri_rt_`, for every runtime entry including the host ones | VALUE-MODEL.md §10 | A split `buri_rt_` / `buri_host_` makes "is this symbol the runtime's" a table lookup in the one place a compiler asks it per call site. |
| The v1 allocator is `malloc`-backed with no size classes | MEMORY.md §5.4 | Nothing observable differs — the header, the capacity, the reuse test and the *defined* `Alloc` cost model are identical — so the free lists can land later under a green suite instead of being co-developed with two backends. |
| The runtime archive is precompiled by `cli/build.rs`, not compiled on demand | BUILD-AND-WATCH.md §2.2 | On demand puts a `rustc` in the build loop and makes the archive hash depend on whatever `rustc` was on `PATH` at *use* time. |
| `Net::fetch` is cleartext `http://` only, and says so — **reversed 2026-08-30**, with its subject | `cli/runtime/http.rs`, `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | `https://` works. It goes through `rustls` over the `ring` provider, the server's certificate is checked against the host's trust anchors, and a certificate that does not check out is a `NetError::Transport` naming what was wrong and which trust set it was checked against. The half of the original row that never depended on the refusal still stands and is now structural: a client that silently downgraded to cleartext would be worse than one that refuses, and `http.rs` cannot downgrade, because the scheme decides one thing — whether the socket is wrapped — and nothing else. What the reversal costs is 1.72 MiB in every binary this compiler produces (§1.1.2), which is over the size budget CI carried and is re-stated there rather than absorbed. A `net`-off toolchain keeps the refusal, and its message names the feature. |
| One bar, **two** admitted sets: the toolchain's and the runtime's — **amended 2026-08-30** | root `Cargo.toml`, BUILD-AND-WATCH.md §1.1, §1.1.1 | One list would have made "tokio is in the compiler" and "tokio is in every program the compiler produces" the same sentence, and they are not the same decision: `libburi_rt.a` is linked into every native binary, so the runtime's set is a set strangers ship. The amendment is a split, not a weakening — the same three clauses, plus a fourth on the runtime's side that the toolchain's does not carry: the set is closed by an **exact list**, asserted as an equality, so a fifth crate and a removal both fail a test. The alternative that lost was one bar and one list with the runtime's entries marked, which loses the fourth clause and the asymmetry that motivates it. |
| The runtime's four networking crates land **referenced by nothing** — **amended 2026-08-30**, two of them now are | `cli/runtime/net.rs`, `manifest.toml` | Landing them with their first caller would have made the archive's growth and the code that needed it one commit, and the growth is the part that is irreversible: the archive is `include_bytes!`d into every `buri` binary. Measured first instead — 6 052 464 → 6 052 488 bytes, twenty-four, because fat LTO drops what nothing reaches — and held there by a CI symbol-table check that the next slice had to move deliberately. It did: `rustls` and `ring` left the "must be absent" list and joined a "must be present" one in the commit that linked them, and the archive went to 7 857 056. `tokio`, `hyper` and `tungstenite` are still referenced by nothing and the check still says so. The decision worked exactly as designed — the 1.72 MiB was a number in a report before it was a number in a binary. |
| The archive's feature list is a **file beside the archive**, and the refusal for a missing one is a **diagnostic before codegen** | `cli/build.rs`, `backend/runtime_native.rs`, `backend/mod.rs`, `docs/errors/networking-not-available.md` | Three ways the toolchain could learn whether its runtime has `net` were open: a `cargo:rustc-env`, a byte written beside the archive, or reading `buri_rt_net_capabilities` back out of the archive's symbol table. The file wins for the reason the baked digest is a file — one `OUT_DIR` written by one run of the build script, so a stale directory cannot pair one build's bytes with another's answer — and it generalises to `net-h3` as a second line rather than a second mechanism. Reading the symbol table would make the toolchain parse `ar` and Mach-O/ELF to learn something the script already knew. What it is *for* is the second half: `Backend::missing_intrinsics` reports the `host.HostListen.*`/`HostSockets.*`/`HostTasks.*` family as missing when the archive has no `net`, so the failure is a sentence naming the operations and the feature, before code generation, rather than an unresolved `buri_rt_*` symbol from `cc`. The refusal landed **before the keys exist**, on purpose: the alternative is that the first toolchain built without networking meets them as a link error. |
| `rustls` is admitted with **no crypto provider** — **reversed 2026-08-30**; the provider is `ring` | `cli/runtime/manifest.toml`, `cli/build.rs`, BUILD-AND-WATCH.md §1.1.2 | Deferred until the bytes were bought rather than spent, which is now. `ring` over `aws-lc-rs` because `aws-lc-rs` wants `cmake` at build time and `ring` wants a C compiler the toolchain already requires for the stencil library and for every link; over the pure-Rust providers because `rustls-rustcrypto` says of itself that it is unaudited and not for production, and this archive is in every binary a stranger ships. The "turns degrades-rather-than-breaks into breaks" objection was real and is answered rather than accepted: `cli/build.rs` **probes** for `cc` before the build and falls back to `--no-default-features` with a `cargo:warning`, so a host without one gets a working toolchain, working `http://`, and an `https://` that refuses at run time naming the feature. A probe rather than a retry-on-failure, because retrying a failed compile with the feature off would also hide a bug in the runtime's own TLS code as a silently net-less toolchain. |
| Trust anchors come from the **host's PEM bundle**, with `SSL_CERT_FILE` overriding — and from no crate | `cli/runtime/tls.rs`, BUILD-AND-WATCH.md §1.1.2 | The two crate answers both lose on the bar's first clause. `webpki-roots` is a quarter-megabyte of *data this repository would ship*, pinning the trust set to a crate version rather than to the machine, so a user who installed a corporate root would have told their machine something a Buri program could not hear. `rustls-native-certs` reads the right thing and costs three transitive crates plus a link-time `Security.framework` on macOS — which a `staticlib` handed to `cc` by `build/link.rs` cannot carry without every artifact's link line growing a flag. Reading `/etc/ssl/cert.pem` and its four Linux spellings is forty lines. What it does not do is read the macOS keychain, and that is what `SSL_CERT_FILE` is for — the spelling OpenSSL, `curl` and `git` already honour, so it is one a user has met. Not cached across calls: a `OnceLock` would save a millisecond against a handshake that costs tens and would make "which roots" depend on when in the process the first request happened. |
| The runtime crate's own unit tests are **run**, by a test in the toolchain's suite that shells out to `cargo test` | `cli/tests/native/runtime.rs`, `cli/build.rs` | `cli/runtime` is a package that is deliberately not a workspace member and whose manifest is deliberately not named `Cargo.toml`, so `cargo test -p buri` could not reach inside it and no CI step did either — fifty-odd assertions about the float formatter, the UTF-16 comparison, the handle table and the allocator had been written and never executed. The `https://` slice needed a home for a test that starts a `rustls` server, and the only `rustls` in this repository is inside that package: the toolchain's own crate cannot grow a dev-dependency on it without failing `dependencies_stay_behind_the_bar`. So the seam was built rather than the bar bent. The path comes from `cargo:rustc-env=BURI_RT_PKG`, written by the build script that assembled the package, and the nested `cargo` gets the same environment scrubbing the build script's does. |
| The runtime's cargo package is **assembled in `OUT_DIR`**; its manifest in the tree is `manifest.toml` | `cli/build.rs` §1, BUILD-AND-WATCH.md §2.2 | `cargo package` skips any subdirectory of a package that holds a `Cargo.toml` — unconditionally, ahead of `include`/`exclude`, in both its listers — so `cli/runtime/Cargo.toml` deleted the whole directory from the published crate and a registry `cargo install buri` failed in the build script with nothing to compile. `include = ["runtime/**"]` was tried and does not override it. Publishing `buri-rt` as its own crate is the other answer and remains available; it is a registry decision with a release process attached, and this one is a rename. What it costs is `cd cli/runtime && cargo build`, which no longer resolves — the build has one driver and it is `cli/build.rs`. |
