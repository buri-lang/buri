     Deleting the field means editing every literal, and those are exactly the
     places computing a value for nobody.

     If callers outside this library read the field, it belongs on the library's
     surface. The rule never reports exported fields of a type lib.buri
     re-exports (or testing/lib.buri, under testing/).

     Two things read every field at once, so their types are never reported:

     - a derived Equal, Ordered, Hash or Show;
     - handing the value to the runtime, or comparing it structurally.

   = a type nothing names, builds or matches is a shape the program does not have
   = fix: delete it, or use it — a type meant to be published belongs on the library's surface

     An unused type is usually one of three things:

     - A leftover. Delete it, with anything that only supported it: its impl,
     its derive, the constructor nobody calls.

     - Meant to be published. Re-export it from lib.buri. The rule never
     reports a name on the surface. Types under testing/ are measured against
     testing/lib.buri.

     - Meant to be wired in. The code that builds it was never written. Write it.

     A type's own impl and derive blocks don't count as uses, so a dead type
     with ten methods is still dead.
