   = `ignore` is the one way to drop a `Result`, so every place a failure is deliberately unhandled is one of these
   = fix: handle the error with `match`, propagate it with `?`, or keep `ignore` if dropping it is deliberate

     A dropped Result is a failure nobody read. Sometimes that's the right call;
     this rule puts every such call in one report.

     The real fix is to handle the error. match on the Result and answer the
     .Err arm (count it, report it, fall back), or use ? to hand it to a caller
     who can.

     Don't write the drop out by hand. This handles nothing:

       match (io.println(ctx, line)) {
           .Ok(_written) => (),
           .Err(_error) => (),
       }

     It's ignore() spelled out, minus the greppability, and hand-rolled-ignore
     reports it too.

     let _ = someResult() and a bare Result statement are already a type error,
     result-discarded, so ignore is the only drop left to report.

     Prints are no exception. Stdout and Stderr answer Result<(), IoError>
     because pipes close, so io.println(ctx, x).ignore() is a drop like any
     other. A program that cares matches on the print, as buri init's template
     does.

     If the failure truly doesn't matter, keeping the ignore and letting the
     warning stand is fine. The point is that somebody decided.
