  |             ^

  = an `impl` names a trait without arguments, so there is nowhere to say what the trait's own parameters are bound to
  = fix: move the parameters onto the methods that need them, as in `fn read<T>(self, id: Int): T;`

    What to do
    ──────────

    Move them onto the methods that need them:

      trait Store {
          fn get<T>(self, key: Str): T;
          fn put<T>(self, key: Str, value: T): ();
      }

    A method may take its own type parameters anywhere a trait or an effect can
    go. Show.show<C: Allocator> and Ui.memo<T> are both in the standard library.

    Why
    ───

    You write a conformance as impl Store for Disk { ... }, and that syntax has
    no place for the trait's arguments. Store<Str> and Store<Int> would be one
    implementation with nothing to say which, so the refusal lands at the
    declaration rather than as a wrong program later.
