error: a `Result` may not be discarded [result-discarded]
 --> cmd/effect_method_on_a_context/main.buri:7:3
  |
7 |   let _ = ctx.println("ready");
  |   ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
  |
  = fix: consume it: `?` to propagate, `match` to handle both cases, `.withDefault(...)` to supply one — or, when you really mean to drop it, the explicit and greppable `.ignore()`

    What to do
    ──────────

    Consume it: ? to propagate, match to handle both cases, .withDefault(...) to
    supply one — or, when you really mean to drop it, the explicit and greppable
    .ignore().

    Why
    ───

    There are two places you can throw a Result away and no third: bound to a _
    in a let, or left standing as an expression statement. Both are this error,
    so must-use is total rather than a convention. .ignore() is then the single
    spelling of a deliberate drop, which buri lint reports as discarded-result.

    The compiler looks for the _ anywhere in the pattern, not only at its head,
    so let (count, _) = (1, mayFail()); is this error too.

error: `Stdout` is an effect, so `println` is not called on a context [effect-method-call]
 --> cmd/effect_method_on_a_context/main.buri:7:15
  |
7 |   let _ = ctx.println("ready");
  |               ^^^^^^^ called as a method
  |
  = the import is `from "core/io" import * as io;`
  = fix: call it through `core/io`: `io.println(ctx, text)`

    What to do
    ──────────

    Hand the context to the function that performs the operation. Every effect
    method has one, and the diagnostic names both it and the module it comes
    from. ctx.println("hi") becomes io.println(ctx, "hi"), ctx.readFile(p)
    becomes fs.readText(ctx, p), ctx.allocate(n) becomes alloc.allocate(ctx, n).

    Why
    ───

    A context is the set of things a program may do. You write it down so a
    reader can see what a function reaches for. x.f(y) hides that. The receiver
    is the smallest, quietest part of a call, so an effect performed through one
    reads like a method on an ordinary value. Passing the context as an argument
    puts the authority where the reader is already looking, and it splits the
    two halves — *which* effect, and *what* it does — into two names.

    It also settles a question the method form left open. Method lookup through
    a bound searches every effect the bound declares, so two effects declaring
    the same verb make that verb ambiguous for everybody who binds both. Ui.read
    and Watch.read are the shipped case. A module-qualified call cannot be
    ambiguous, so the vocabulary stops being one flat namespace shared by every
    effect that will ever exist.

    Two layers sit below this line and keep the method form. The standard
    library holds the wrapper functions, so its bodies are the only code that
    reaches an effect at all. And the body of an impl that *supplies* an effect
    implements the operation, which is what keeps an attenuating wrapper
    writable:

      # from "core/effect" import { IoError };
      # from "core/fs" import { FsRead, FsWrite, Path };

      struct ReadOnly<C>(C);

      impl<C: FsRead> FsRead for ReadOnly<C> {
          fn readFile(self, path: Path): Result<Str, IoError> {
              self.0.readFile(path)
          }

          fn fileExists(self, path: Path): Bool {
              self.0.fileExists(path)
          }

          fn readDir(self, path: Path): Result<[Str], IoError> {
              self.0.readDir(path)
          }

          fn readFileBytes(self, path: Path): Result<[U8], IoError> {
              self.0.readFileBytes(path)
          }
      }

      // Nothing here forwards, so this half needs no bound on `C` at all — which is
      // what the filesystem being two effects buys a decorator: the half that
      // refuses restates eight methods and the half that forwards restates four,
      // and neither had to know about the other.
      impl<C> FsWrite for ReadOnly<C> {
          fn writeFile(self, path: Path, body: Str): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn writeFileBytes(self, path: Path, body: [U8]): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn appendFile(self, path: Path, body: [U8]): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn renameFile(self, source: Path, destination: Path): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn removeFile(self, path: Path): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn removeDir(self, path: Path): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn makeDir(self, path: Path): Result<(), IoError> {
              .Err(.ReadOnly)
          }

          fn syncFile(self, path: Path): Result<(), IoError> {
              .Err(.ReadOnly)
          }
      }

    That delegation cannot become fs.readText(self.0, path), because the wrapper
    is bounded Alloc + FsRead and this impl carries only C: FsRead. The
    carve-out grants nothing new: an implementor reaches only an inner context
    somebody already handed it.
