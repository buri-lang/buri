     Those two lines are the whole story: what the position wanted, and what is
     there. Only a conversion with a name earns a fix line beside them.

     Numbers do not convert on their own
     ───────────────────────────────────

     Convert explicitly. The diagnostic names the conversion: .toI64() is exact
     for every I32, while a narrowing one returns a Result because not every
     value fits.

     A bare numeric literal is reported as Int or Float, the type it takes when
     nothing pins it. It is not held to that: annotate it — let x: F64 = 1.0, or
     let x: U8 = 1 — and it becomes any type of the same kind.

     There is no promotion of any kind, in either direction. A language that
     widened silently would make the width of an arithmetic result depend on the
     shape of the expression rather than on what you wrote.

     A .Variant is a variant
     ───────────────────────

     A leading dot takes its enum from the position it is written in, so a
     position that is not an enum has nothing to give it, and expected is the
     type to write instead. What is reported as found is a variant rather than a
     type, because .Const on its own is not one — and guessing an enum from the
     payload would put a type in front of you that nothing in your program says.

18 |   ctx.read<Str>(id)
   |       ^^^^ called as a method
   |
   = fix: call it through `ui/signal`: `aSignal.get(ctx)`

     What to do
     ──────────

     Hand the context to the function that performs the operation. Every effect
     method has one, and the diagnostic names both it and its module.
     ctx.println("hi") becomes io.println(ctx, "hi"), and ctx.readFile(p)
     becomes fs.readText(ctx, p).

     Why
     ───

     A context is the set of things a program may do, and you write it down so a
     reader can see what a function reaches for. The receiver is the quietest
     part of a call, so x.f(y) hides that. Passing the context as an argument
     puts the authority where the reader is already looking, and splits the two
     halves — *which* effect, and *what* it does — into two names.

     It also keeps the vocabulary from being one flat namespace. Method lookup
     through a bound searches every effect the bound declares, so Ui.read and
     Watch.read would be ambiguous for anybody binding both. A module-qualified
     call cannot be.

     Two layers below this line keep the method form: the standard library's
     wrapper functions, and the body of an impl that *supplies* an effect. The
     second is what keeps an attenuating wrapper writable — its readFile calls
     self.0.readFile(path), reaching only the inner context it was handed.
