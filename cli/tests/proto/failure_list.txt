# --- `Any` in JSON, which needs a type registry --------------------------------
#
# proto3 JSON writes an `Any` as the message it holds, `{"@type": url, ...}`, so
# a reader has to know every type a URL can name and a writer has to decode the
# bytes as one. A generated module knows only the types its schema reaches, and
# nothing hands it the rest, so `core/proto/any` writes and reads an `Any` as
# its two fields. The binary format is unaffected.

# --- A JSON writer that cannot fail -------------------------------------------
#
# A `Duration` or `Timestamp` outside the range proto3 JSON can write, or with
# nanos of the wrong sign, should fail to serialize. `encodeMJson` answers a
# `Json` rather than a `Result`, so such a value is written as it is. Making it
# refuse is a change to every generated encoder's signature.

# --- Unknown fields are dropped rather than retained --------------------------
#
# Decoding skips a field the schema does not know, which is the forward
# compatibility every edition has; it does not *keep* the bytes, because a
# generated struct has nowhere to put them. A message decoded from a newer
# schema and re-encoded therefore loses what that schema added. Stated in
# `core/proto`.
#
# Keeping them would mean a field for the bytes on every generated struct, and
# every struct literal written without `..defaultM()` would stop compiling.
# That breaking change is a decision about the mapping, not a codec fix.
# (2 tests)
Required.Proto3.ProtobufInput.UnknownOrdering.ProtobufOutput
Required.Proto3.ProtobufInput.UnknownVarint.ProtobufOutput
