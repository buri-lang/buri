---
name: documentation
description: Documentation style guide and considerations for cli/src/docs and other markdown files
---

- Lead with code snippets, explain in text only what cannot be described in code.
- Avoid numbering unless order carries information.
- Use active voice, always.
- Be concise. Every sentence removable is removed. No section headers where a list will do.
- Code comments are one or two lines, and comment only when avoiding confusion.
- Yagni, remove anything that's unnecessary or duplicated.
- Write in clear, plain, conversational English.
- Avoid clinical jargon, corporate buzzwords, and overly dense sentence structures.
- Break complex ideas into simple, punchy sentences.
- Speak like an expert human peer, not an academic textbook.
