# Bug #345: a guard reading a consumed scrutinee

- Cause: `middle/rc.rs`'s `Scan::arm` left a consumed scrutinee out of what a guard holds. A guard that read it, as in `match (s) { _ if s.contains("x") => …, _ => … }`, released it on the false path, and the arm it fell to released it again. It wasn't about `Scope`: any heap value the match consumes hit it, on both native backends.
- Fix: the guard holds the scrutinee across itself, and the arm releases it at its entry.
- Tests: ten blocks at the end of `cli/tests/conformance/lib/memory/test/guards.buri` (method call, a fall-through arm that returns the scrutinee, a consuming call, `&&`, a closure capture, an enum payload, a struct pattern, a list, a map, recursion), and one in `cli/tests/conformance/lib/ui/test/render.buri` (the issue's `describe`). Each one failed first under the heap check on stencil and on LLVM `--release`.
